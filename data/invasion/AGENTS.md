# data/invasion — 침공 방어체 카탈로그

## 목적

침공 3레이어(ADR-0017)에서 **방어자가 수집·배치하는 것들의 데이터**. 레이어별로 카탈로그가 갈린다 —
L1 편대, L2 설비·맵 템플릿, L3 기물·방어 보스.

## 주요 파일

| 파일 | 설명 |
|---|---|
| `catalog.ts` | 카탈로그 레지스트리 |
| `formations.ts` | L1 **편대** 8종 — 고유 진형·공격 패턴을 내장한다(방어자는 슬롯 순서만 정한다) |
| `facilities.ts` | L2 **설비** 9종 — 벽부착 방어포 · 기믹 해저드 · 드론 스포너 |
| `mapTemplates.ts` | L2 회랑 맵 템플릿 3종 + **설치 소켓 좌표 테이블**(직선 12 · 굴곡 10 · 병목 8) |
| `props.ts` | L3 코어방 **기물** — 설비와 문법은 같되 코어방 전용 카탈로그 |
| `defenseBosses.ts` | L3 **방어 보스** 레지스트리 |
| `garrison.ts` | **기본 수비대** — 빈 슬롯·소켓을 행성 소속 최저 등급으로 자동 충원해 빈 화면을 막는다 |

## AI 에이전트용

### 이 디렉터리에서 작업할 때

- **소켓 수 자체가 예산**이다(구 배치 포인트 예산제는 M7a 에서 폐지). 몰빵 배치는 맵에 내장된
  소켓 밀도 상한이 구조적으로 막는다.
- 기본 수비대는 **방어자 소유물이 아니다** — 강화·풍화 대상이 아니고, 방어자가 수집한 방어체로
  교체될수록 강해지는 성장 공식을 만든다.
- 어픽스는 **"방어체 어픽스"** 로 전체 표기한다(장비 어픽스·엘리트 어픽스·모듈 어픽스와 별개).
- 카탈로그를 늘리면 sim 런타임(`src/sim/invasion/`)과 배치 UI(`src/ui/pixi/defenseCommand.ts`),
  그리고 SQL 검증(`invasion_layers_valid`)이 함께 움직인다 → **Edge Function 재배포 대상**.

### 테스트 요구사항

`tests/invasion*.test.ts`(다수). 밸런스는 `tests/invasionBalance.test.ts`(**sim 레인**).

### 공통 패턴

- 레지스트리 + 스펙 상수. 좌표·경로는 카탈로그가 내장하고 방어자는 선택만 한다.
