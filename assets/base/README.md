# 기지 화면 시네마틱 자산

기지 허브(`src/ui/pixi/baseMap.ts`)의 배경·타일 아트다. **이 폴더의 `.webp` 가 진실**이고,
아래 절차는 재생성이 필요할 때를 위한 기록이다.

## 파일

| 파일 | 크기 | 역할 |
| --- | --- | --- |
| `base_backdrop.webp` | 1376×768 RGB | 오스카 유적 안의 격납고 홀. 풀블리드 배경. |
| `base_bld_<key>.webp` | 848×528 RGB | 건물 타일 일러스트 7종 |
| `base_launch.webp` | 848×528 RGB | 출격 카드(격자 8번째 칸)의 발사 게이트 |

`<key>` 정본은 `src/ui/pixi/baseTextures.ts` 의 `BASE_BUILDING_KEYS` 이고, 이름 규약은
`baseBuildingAssetName()` 한 줄이다. `tests/baseAssetPresence.test.ts` 가 목록 ↔ 실물을
**양방향**으로 대조한다.

## 타일 아트가 848×528 인 이유 — 밴드 종횡비에 미리 맞춘다

타일은 카드 상단 71%(`BAND_RATIO`)를 일러스트가 채운다. 카드가 424×352 이므로 밴드는
`424 × 250`, 종횡비 **1.605:1** 이다. 자산을 정사각(1024²)으로 두면 런타임 크롭이 세로를
크게 잘라 **탑처럼 세로로 긴 건물의 꼭대기와 기단이 함께 날아간다**(실제로 관제탑·기록
보관소에서 그렇게 됐다).

그래서 **자산을 밴드 종횡비로 미리 크롭**하고, 크롭 시 **건물별 세로 초점**을 따로 준다
(높은 건물은 위를, 넓은 건물은 가운데를). 런타임 크롭은 그 결과 항등이 된다.

⚠️ `BAND_RATIO` 나 카드 치수를 바꾸면 이 종횡비가 어긋난다. 아래 스크립트의 `AR` 을 같이
고쳐서 재출력해야 한다.

## 그레이드 패스 — 7장을 "한 기지의 건물"로 묶는 단계

생성형으로 뽑은 7장은 그냥 두면 **상단 하늘 띠의 휘도가 L 34~79(Δ45), 색온도가
R−B −19~+5(Δ24)** 로 흩어진다. 그러면 "잘 그린 그림 7장"이지 "한 기지의 7개 건물"이 아니다
(AAA 비평 판정). 그레이드 후 **L 60.0~64.7(Δ4.5) · R−B −7.4~−8.8(Δ1.3)**.

방법은 **감마만** 쓴다: `out = 255·(v/255)^g`. 0 과 255 를 보존하므로 **클리핑이 원리적으로
없다** — 곱연산 게인처럼 하이라이트를 태우지 않는다. 감마는 하늘 띠 평균이 목표에 닿도록
풀어서 구한다(휘도 1회 + R·B 채널 각 1회).

⚠️ **한계**: 감마는 색상축을 크게 옮기지 못한다. 원화가 애초에 중성(R−B ≈ 0)인 장은 따뜻한
대역으로 못 끌고 온다 — 그런 장은 **재생성이 답이다**(관제탑·격납고가 그랬다).

## 재생성 절차

1. **생성** — 배경은 `nano-banana-pro` `text_to_image` `aspect_ratio: "16:9"`(9 크레딧).
   건물·출격은 `meshy_image_to_image` 로 **기존 자산을 레퍼런스**로 넣어 붓을 맞춘다
   (9 크레딧/장, 출력은 **항상 1024²** — `aspect_ratio` 파라미터가 없다).
2. **JPEG 확인** — Meshy 가 확장자는 `.png` 인데 실제로 JPEG(`FF D8`)를 내려줄 때가 있다.
   `[System.Drawing.Image]` 로 한 번 변환해 넘겨라(Pillow 는 알아서 읽지만 리포의
   `scripts/lib/png.mjs` 는 "not a PNG" 로 죽는다).
3. **크롭 + 그레이드 + WebP** — 한 스크립트로 한다. 세 단계를 나누면 초점·감마 기준이 갈린다.

프롬프트 규칙:
- 길이 상한 **600자**(Meshy MCP 검증). 모델 인자는 `ai_model`(`model` 아님).
- `painterly digital concept art` 를 쓰고 **`hand-painted` 는 금지**(캔버스 천에 그린 유화를
  찍은 사진이 나온다). `no canvas texture / no picture frame / no border / no text` 명시.
- 건물은 **"구조물 하나, 중앙, 3/4 시점, 프레임 안에 완전히 들어오게"** 를 못 박아라. 안 그러면
  내부 전경이 나오거나(격납고 1차) 첨탑이 프레임 밖으로 나간다(관제탑 1차).
- 팔레트를 문장으로 고정: `muted golden-ochre stone, deep teal and magenta, warm gold lamplight`.

## 배경에 대한 미해결 과제

현재 배경은 `"The central area is deliberately empty"` 로 생성했다 — 타일이 앉을 자리를
비우려는 의도였다. 그런데 **격자 사이 거터가 정확히 그 빈 구간에 걸린다.** 원화의 거터 위치
실측이 평균 37.3 / 87.2 / 37.4 에 **std 7.4 / 27.2 / 9.3** 이라, 거터 1·3 은 텍스처가 거의
없는 어두운 세로 띠다. 국소 톤매핑으로 대비를 끌어올려도 **없는 디테일은 만들 수 없다**.

배경을 다시 만든다면 **4열 격자에 맞춰 설계**해야 한다 — 화면 폭 **26% · 50% · 74%** 지점
(= 거터 x 위치)에 석조 기둥이 서 있어, 타일이 기둥 사이에 앉고 UI 가 건축의 일부로 읽히게.

## 용량

WebP 합계 **≈310KB**. `tests/baseAssetPresence.test.ts` 의 상한은 560KB 다. 기지는 첫 페인트
경로가 아니지만(런 한 번을 거쳐야 도달한다) 장수가 가장 많으므로 상한을 건다.
