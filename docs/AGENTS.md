# docs — 기획·결정 문서

## 목적

**왜 그렇게 만들었는가**를 담는다. 코드가 답하지 못하는 질문(설계 의도, 되돌리기 어려운 결정,
측정 절차)이 여기 있다.

용어 정본(`CONTEXT.md`)과 작업 규약(`CLAUDE.md`)은 리포 루트에 있다.

## 주요 파일

| 파일 | 설명 |
|---|---|
| `GDD.md` | 게임 기획 정본 |
| `balance-check.md` | `pnpm balance` 하네스의 **절차·인자·게이트 근거·측정 사각지대 정본** |
| `player-power-reference.md` | 플레이어 파워 참조표 |

## AI 에이전트용

### 이 디렉터리에서 작업할 때

- **구현이 ADR 과 충돌하면 먼저 ADR 을 고친다**(또는 새 ADR 로 뒤집는다). 코드만 바꾸면 다음 레인이
  옛 결정을 근거로 되돌린다.
- 문서는 한글로 쓴다. 용어는 `CONTEXT.md` 를 따르고 금지어(`_Avoid_`)를 피한다.
- 계획 문서(`.omc/plans/**`)와 다르다 — 저기는 세션 산출물이고 여기는 **유지되는 정본**이다.
  특히 `.omc/plans/**` 다수에 있는 "매 커밋 `pnpm test` 전체"는 낡은 문구다(현행은 `CLAUDE.md` 3단).

### 테스트 요구사항

문서에는 테스트가 없다. 다만 문서가 인용하는 수치는 실측 출처(명령·날짜·표본)를 함께 적는다 —
이 리포는 "설계값과 실측이 어긋난 채 굳은" 이력이 있다(구 par 150초 vs 실측 95초).

### 공통 패턴

- ADR 은 번호 + 결정 한 줄 제목. 폐기된 결정도 지우지 않고 개정 이력을 남긴다.
