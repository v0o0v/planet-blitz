# 아이콘 축은 개체가 아니라 성질 단위로 잡는다

장비·스킬·파워업에 이미지를 넣기로 하면서, **무엇이 같으면 같은 그림인지**(=아이콘 축)를 정해야 했다. 개체 단위로 세면 장비는 애초에 불가능하고(시드에서 롤되므로 개체 수가 무한이다), 스킬은 60노드, 파워업은 24종이다. 결정: **아이콘 축을 개체가 아니라 개체를 구별짓는 성질에 건다** — 장비는 슬롯+무기타입, 스킬은 스탯+티어대, 파워업은 스탯+티어대+무기타입이다. 유니크 장비와 캡스톤만 개별 아트를 갖는다.

이유는 실측이다. 스킬 60노드를 전수 조사하니 트리 구조 자체가 **12스탯 × 5티어**였다. `maxHpFlat` 7노드(보강 장갑·내구 격벽·복합 장갑·충격 완화·중장갑 도금·강화 프레임·타이탄 도금)는 수치만 +6 → +14로 오르는 같은 물건이고, `moveSpeedPct` 10노드도 전부 추진기다. 64px 아이콘으로 "보강 장갑"과 "복합 장갑"을 구별되게 그리는 것은 생성 모델에게 불가능한 주문이며, 만들어도 플레이어가 구별하지 못한다. 60장을 만들고도 결과는 스탯 단위 세트와 같아지고 비용만 배로 든다. 파워업도 같은 구조였다(데미지 +N% 6종·최대 HP 3종). 노드를 유일하게 식별하는 일은 이미 **이름**이 하고 있으므로, 아이콘이 떠맡을 일은 "이게 무슨 스탯이냐"를 즉시 읽히게 하는 것뿐이다.

## 결정 사항

- **장비 30장.** 슬롯 7종 중 주무기·보조무기는 `Item.weaponType`(발칸·스프레드·레일건·미사일·빔)으로 쪼개 15장, 유니크 15종은 개별 아트. 유니크는 고정 옵션과 고유 효과를 갖는 이름 있는 아이템이라 성질 단위로 묶을 대상이 아니다.
- **스킬 35장.** 5티어를 저(0~1)·중(2~3)·고(4) 세 **티어대**로 묶어 (스탯 × 티어대) 조합을 세면 32장이다(스탯마다 존재하는 티어대가 달라 12×3=36 이 아니다 — `rangeFlat` 은 노드가 하나뿐이라 1장, `bulletCount`·`bulletSpeedPct` 는 2장). 캡스톤 3개는 `perPoint: 0` 인 질적 노드라 스탯 아이콘을 붙이면 거짓말이 되므로 개별 아트.
- **파워업 신규 0장.** 스킬 세트의 스탯 아이콘을 기본으로 깔고, `PowerupDef.weaponType` 이 있는 것은 장비 세트의 무기 아이콘을 작은 배지로 겹치며, **스킬 세트가 스탯마다 갖고 있는 티어대(저·중·고)를 세 번째 축으로 같이 쓴다**. 처음 이 ADR 은 스탯+무기타입 둘만으로 24종이 전부 구별된다고 적었는데, 매핑을 실제로 짜서 세어 보니 **17종으로 접혔다** — 배지를 붙일 무기 축이 없는 파워업끼리 겹쳐 충돌 7건이 남았다(최대 HP 3종이 한 그림, 데미지·연사·이속·대시·자석이 각 2종씩). 무기 파생 8종은 배지 덕에 처음부터 전부 갈렸으므로 문제는 배지 없는 16종 쪽이었다. 해소는 같은 스탯의 파워업을 `PowerupDef` 의 실제 수치 크기 순으로 저·중·고에 나눠 담는 것이다(야전 응급팩 +15 = 저, 강화 장갑 +25 = 중, 보강 도금 +30 = 고). 티어대 아트는 스킬 세트가 어차피 만드는 것이라 **신규 생성이 0장이라는 결론은 그대로 유지되고**, 조합은 24종 전부가 구별된다. 매핑의 진실의 원천은 `src/ui/powerupIcons.ts` 다.
- **도발 스티커 12장.** 이것만 성격이 다르다 — 생성이 아니라 **결함 복구**다. 이모지가 Pixi 관제탑의 `stripEmoji()` 에 통째로 걸려 지금 화면에 나오지 않는다(ADR-0014 Consequences 의 알려진 대가).
- **등급은 아이콘 축이 아니다.** 노말·매직·레어는 같은 그림이고 등급은 셀 테두리와 등급색 글로우로만 읽힌다. 유니크만 그림 자체가 고유해 예외다.
- **방어 카드 25종과 어픽스 24종은 범위 밖.** 어픽스는 툴팁 텍스트 줄이라 16px 자리밖에 없고, "예리한/잔혹한/치명적인"처럼 같은 스탯의 단계 차이가 많아 위와 같은 이유로 구별 아트가 성립하지 않는다.
- **시각 레지스터는 이 ADR 이 정하지 않는다.** 장비 아이콘이 카툰나무풍(메타 UI)에 속하는지 SF 픽셀아트(전투 화면)에 속하는지는 샘플 대조로 실증한 뒤 별도로 기록한다. → **ADR-0016 에서 결정됨**: 어느 쪽도 아닌 세 번째 레지스터(앵커 `pb-equip-icon`).

## Consequences

- **연구소 레이아웃 재구성이 강제됐고, 그 뒤 전제가 바뀌어 다시 풀렸다.** 노드 셀에 아이콘이 들어가면 이름 폭이 97 → 57px 로 줄어 한글 이름이 읽히지 않는다. 그런데 2열을 유지한 채 셀을 키우는 것은 산술적으로 불가능했다 — 노드 그리드 가용 세로는 530px(`NODE_TOP` 130 → `CAPSTONE_Y` 660)이고 10행 × 52 = 520px 로 여유가 10px 뿐이라, 셀을 68px 로 키우면 10행에 760px 가 필요한데 패널을 1080 천장까지 늘리고 리스펙 버튼을 밀어내도 634px 밖에 못 만들었다. 10행이라 세로 증분이 10배로 곱해지는 것이 원인이었다. 그래서 **열을 늘려 행을 줄이는 것** 말고는 답이 없었고, 파생 스탯 미리보기 패널을 화면 하단 가로 띠로 내려 계열 패널을 461 → 620px 로 넓힌 뒤 4열 × 5행(셀 119×95)으로 재배치했다. 이 산술을 성립시킨 전제는 **"한 계열의 20노드를 한 화면에 전부 보여야 한다"** 하나뿐이었는데, 실화면 검증에서 사용자가 "각 파트에는 찍은 스킬만 보여주고, 버튼을 누르면 팝업에서 전체를 보며 거기서 다시 찍게 해달라"고 요구하면서 **그 전제 자체가 사라졌다**. 본 패널이 지는 짐은 이제 20노드가 아니라 투자한 노드뿐이고, 전체 목록은 세로 스크롤 팝업이 맡으므로 세로 천장의 제약을 받지 않는다. 따라서 4열 × 5행은 더 이상 강제가 아니며, 본 패널은 아이콘 + 이름 + 포인트가 한 줄에 들어가는 2열 목록(246×43)으로 되돌아갔다 — 한 계열을 끝까지 찍어도 10행 × 2열 = 20 이 스크롤 없이 들어간다. 계열 패널 620px 와 하단 가로 띠는 그대로 남는데, 이제는 산술적 강제가 아니라 이미 검증된 화면 구성이라 유지하는 것이다.
- **등급 신호가 절반으로 준다.** 지금 슬롯 셀은 등급을 테두리 색 **그리고** 글리프 색 두 곳으로 말하는데(`src/ui/pixi/slotGrid.ts`), 컬러 아이콘이 들어오면 후자가 사라진다. 테두리 3 → 4px 와 등급색 내부 글로우를 Graphics 로 보완한다(생성 0장). 인벤토리가 빨라질수록 등급 스캔이 느려지는 것을 막는 조치다.
- **같은 스탯의 노드는 같은 그림이 된다.** "예리한"과 "잔혹한"이 같은 damagePct 아이콘을 쓰는 것은 결함이 아니라 이 결정의 내용이다. 구별은 이름과 수치가 한다.
- 티어대 경계(저 0~1 / 중 2~3 / 고 4)를 나중에 바꾸면 아이콘 재매핑이 필요하다. 밴드는 데이터가 아니라 아이콘 목적의 묶음이므로 `data/skills.ts` 의 `tier` 를 건드리지 않는다.
- 아이콘이 없거나 로드에 실패하면 기존 텍스트 글리프(`itemGlyph`)와 노드 이름으로 폴백한다 — `uiTextures.ts` 의 null 폴백 규약을 그대로 따르므로 자산 하나가 빠져도 화면은 죽지 않는다.
