# 배치 프리뷰는 실침공 월드를 재사용한다 (정지 월드 렌더)

방어 사령부를 "실제 게임화면을 보면서 편집"하는 통합 화면으로 재편하면서(2026-07-19 그릴링), 배치 프리뷰를 무엇으로 그릴지 결정해야 했다. 결정: **에디터가 실제 `createWorld(침공 config)`로 정지 월드를 만들고, 침공 런과 동일한 렌더 경로(entityRenderer + 게임 캔버스)로 1프레임씩 그린다.** 배치가 바뀔 때마다 월드를 재생성한다(수십 엔티티라 비용 미미). 정지 월드는 라이브 런 상태(`world` 변수)와 분리된 별도 참조로, 게임 루프에 태우지 않고 recorder도 붙이지 않는다 — sim은 한 틱도 진행되지 않으므로 리플레이·오염 런·정산 규칙과 무관하다.

대안은 에디터 전용 경량 렌더(텍스처를 직접 배치하는 별도 Pixi 레이어)였다. 경량 렌더는 월드 생성 비용이 없고 구조가 단순하지만, 침공 렌더와 **이중 관리**가 된다 — 스프라이트 교체·스케일 조정·신규 배치물(예: 새 포탑 종류)이 생길 때마다 두 경로를 함께 고쳐야 하고, 하나만 고치면 "편집 화면에서 본 모습"과 "침공 때 보이는 모습"이 조용히 어긋난다(드리프트). 이 기능의 존재 이유가 바로 그 1:1 일치이므로, 일치를 사람이 지키는 규칙이 아니라 **구조로 보장**하는 쪽을 택했다.

## Consequences

- 프리뷰와 침공 화면의 일치가 구조적으로 보장된다 — 렌더 경로가 하나뿐이라 어긋날 방법이 없다
- 배치물 렌더를 고치면(스프라이트·스케일) 프리뷰와 침공 런이 항상 함께 좋아진다
- 에디터가 sim 팩토리(`createWorld`)에 의존하게 된다 — 침공 config 계약이 바뀌면 에디터 프리뷰 생성부도 따라간다
- 정지 월드는 게임 루프·recorder·정산 경로에 절대 연결하지 않는다 — 연결하는 순간 오염 런·리플레이 규칙(ADR-0008)이 끼어든다
- 그리드·사거리 원·진입 지점 마커 같은 편집 오버레이는 월드 밖의 렌더 전용 레이어로 얹는다 — sim 무수정(ADR-0005 결정론 불변)
