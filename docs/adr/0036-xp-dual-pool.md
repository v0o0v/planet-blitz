# 경험치 이원화 — 런 풀과 메타 풀을 가른다

젬 하나가 만드는 XP 가 **런 내 성장**(레벨업 → 파워업 3택)과 **기체 레벨**(영구) 양쪽에 같은 값으로 들어간다 — `src/sim/world.ts:3399` 가 `state.xp`(소비형)와 `state.xpTotal`(누적형)에 같은 `gained` 를 더하고, 둘 다 같은 커브 `xpToNext(level) = 10 + level × 6`(`src/sim/world.ts:359`)를 쓴다. 그래서 **파밍 속도를 바꾸려는 모든 시도가 런 체감을 함께 부순다**: 만렙까지의 시간을 늘리려고 커브를 세우거나 젬 XP 를 낮추면 런 안에서 레벨업이 같은 비율로 줄어 파워업을 거의 못 받고 런이 무너진다. 반대 방향도 같다. 이를 해결하기 위해(2026-07-27 grill 세션) **두 풀을 서로 다른 값으로 채운다** — 젬 수집 1회가 런 풀에는 단계 무관 고정값을, 메타 풀에는 침략 단계에 비례한 값을 넣는다. 두 축을 독립적으로 튜닝할 수 있게 하는 것이 이 결정의 전부다.

**계층 배치는 비대칭이다.** 단계 비례는 sim 이 처리한다(`config.stage` 가 이미 런에 도달해 있다). **저단계 감쇠는 정산 계층(`src/save/settlement.ts`)이 처리한다** — 감쇠는 "표준 진행 경로(ADR-0035) 대비 몇 단계 아래인가"라 **기체 레벨**이 필요한데, 그 값은 `WorldConfig` 에 없고 넣으면 침공 리플레이 제출 스키마·서버 권위 재도출·계약 테스트가 연쇄로 붙는다(침공은 감쇠를 쓰지도 않는다). 감쇠를 sim 에 두면 부작용이 하나 더 있다 — 저단계 런에서 **런 내 파워업까지 굶어** 저단계가 "보상만 적은 곳"이 아니라 "더 어려운 곳"이 된다. 감쇠의 의도와 정반대다.

## Consequences

- **전 골든 재생성 + `verify-invasion` EF 재배포가 확정 비용이다.** 런 풀 값이나 커브가 바뀌면 레벨업 시점이 옮겨지고 → 파워업 롤이 달라지고 → per-tick `hashWorld` 가 달라진다. 침공 런도 런 내 성장을 쓰므로 예외가 아니다. **침공 골든의 바이트 불변은 EF 재배포 불필요의 근거가 못 된다** — 서버가 재실행하는 것은 번들된 sim 소스이므로, 소스가 바뀌면 배포해야 한다.
- **런 내 리듬은 이번 기회에 런당 5~8회 레벨업으로 줄인다**(실측 약 11회). 두 풀이 갈렸으므로 메타 목표와 무관하게 정할 수 있다.
- **HUD 와 정산 화면의 XP 숫자가 서로 달라진다** — 런 중에 보이는 게이지는 런 풀, 정산에서 기체 레벨에 들어가는 값은 메타 풀이다. 같은 이름으로 두면 버그 리포트를 부른다. 표기를 분리한다.
- **XP 는 여전히 클라 권위다.** 재화(크레딧·광물)는 서버 원장(ADR-0027)이지만 기체 레벨·XP 는 클라가 계산해 프로필에 적립하고 서버 save 로 미러링한다. 이 결정이 그 표면을 넓히지는 않는다(감쇠가 정산으로 가도 계산 주체는 그대로 클라다) — 서버 권위 이관은 별개 항목으로 남는다.
- **`LEVEL_CAP = 100` 을 실제로 강제한다.** `grantXp`(`src/save/settlement.ts:220`)에 클램프가 없어 XP 만 있으면 Lv101, 102… 로 계속 올랐고, CONTEXT.md 는 "캡은 100", `tests/guardianLifecycle.test.ts:98` 은 오히려 `LEVEL_CAP + 5` 를 정상으로 기대해 **문서·코드·테스트 3자가 어긋나** 있었다. 캡을 강제하면 초과 XP 는 버려지고 퇴역이 유일한 출구가 되어 세대 순환(ADR-0007·0024) 의도가 살아난다. 해당 테스트 1건을 개정한다.
- **침공은 경험치 축이 아니다.** 침공 런은 `settleRun` 에 도달하지 않으므로(`src/main.ts:1205`) 기체 레벨을 올리지 않는다 — **예비역 소집** 런도 마찬가지다. CONTEXT.md 가 약속했던 "소집 런의 정산 경험치는 활성 기체에 귀속된다"는 코드에 맞춰 철회했다(2026-07-27). 침공 보상은 래더·복제 약탈·설계도 축이고, 신세대 성장은 활성 기체로 도는 PvE 침략이 담당한다.
- 기존 밴드 테스트가 재측정 대상이 된다 — `tests/emergentRunLength.test.ts`(완주 40~150초), `tests/invasionBalance.test.ts`(3밴드 승률). 후자는 **최저 기지 12시드 중 1승**이 여유의 전부이므로(m8 인계 §6) 적용 전에 개별 확인이 필요하다.
