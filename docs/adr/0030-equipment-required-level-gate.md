# 장비 착용 요구 레벨 — 아이템 파워를 현재 기체 레벨에 묶는다

장비는 착용 제한이 전혀 없었고(`Item` 에 requiredLevel 없음, 프로덕션 장착 UI `src/ui/pixi/hangar.ts` 에 착용 게이트 없음) 어픽스 롤 값은 단계와 무관하게 고정이라(단계는 rarity 확률만 스케일, `src/sim/drops.ts`), 저단계 럭키 레어·유니크 하나가 곧 최대 파워였다. 더 근본적으로, 퇴역 후 신규 Lv1 세대 기체가 창고의 엔드게임 장비를 즉시 껴서 세대 리셋의 재성장 루프(ADR-0024)가 껍데기가 됐다. 장비는 모든 파워 축 중 **유일하게 진행도 게이트가 없는 축**이었다(스킬=기체 레벨, 계보=퇴역·소멸, 방어체=자원·승급, 파워업=런 내 획득·소멸). 이를 해결하기 위해(2026-07-24 grill 세션) 각 장비에 **요구 레벨**을 부여하고 기체 레벨 미달 시 착용을 막는다. 요구 레벨은 아이템에서 **순수 파생**하며, **착용 시점의 클라 메타(프로덕션 Pixi `HangarScreen`, `src/ui/pixi/hangar.ts`)에서만** 강제한다. sim 은 부적격 아이템을 아예 못 보므로 상태 해시·세이브 스키마는 불변이다. 코어 모듈·방어체 등 다른 축은 자기 게이트가 이미 있어 대상이 아니다.

**산식(2026-07-24 deep-interview 로 개정):** 요구 레벨은 `itemCombatPower`(수호 스냅샷·소멸에도 쓰이는 함수)와 **분리된 독립 상수 테이블**에서 파생한다 — 노말·매직·레어 = 등급 바닥 + 어픽스 개수 × 가산(placeholder: 노말 1 / 매직 10+2 / 레어 32+3, `TODO(밸런스)`), 유니크 = `UniqueDef.reqLevel` **개별 저작값**(전투형 ~65-75·유틸형 ~15-30). 초기안(`itemCombatPower ÷ 계수` 재사용)은 그 함수를 수호/소멸 밸런스로 재튜닝하면 요구 레벨이 함께 흔들리는 **커플링** 때문에 폐기했고, 유니크를 등급 바닥으로 균일 처리하면 유물 증폭기·도박사의 칩 같은 **유틸형 유니크가 레벨링이 끝나야 열리는 역설**이 생겨 개별 저작으로 바꿨다.

## Considered Options

- **소프트 효율 스케일(레벨 미달 시 효과를 %로 감쇠, 착용은 허용)** — 하드 월이 아니라 창발 난이도 철학에 가깝지만, 효율 배율이 로드아웃 → 상태 해시에 들어가 전 fixture 재생성·서버 재도출 표면이 늘고, "툴팁 수치와 실제 파워 불일치" 가독 저하가 있어 기각. 하드 게이트는 착용 시점 차단이라 해시 불변이다.
- **요구 레벨을 드랍 단계(`ItemSource.stage`)에서 파생** — 럭키 저단계 드랍이 낮은 요구치를 받아 실패 모드 ①(신규 운빨)을 못 막아 기각. 요구치는 **아이템 내재 파워**에서 와야 드랍 위치와 무관하게 강함을 반영한다.
- **어픽스 티어 기반 요구치(D2 정통 — 어픽스마다 레벨 태그, req = max 어픽스 레벨 + 등급 바닥)** — 트윙크까지 정밀 차단하나, 현 게임이 어픽스를 어디서도 티어링하지 않는데 24종 어픽스 + 유니크 레벨 데이터·튜닝 표면을 새로 여는 비용이 1차 이득 대비 커 기각. 전투력 점수(등급 + 깊이)가 충분한 근사이며, 나중에 `itemCombatPower` 산식만 어픽스 강도까지 반영하도록 강화하면 이 아키텍처 그대로 정밀화된다.
- **드랍 강도 단계 스케일(저단계 = 약한 어픽스 롤)** — ADR-0022 의 "완전 병렬"(어픽스 강도 flat, 품질 = rarity 확률 + 특산 테이블) 을 반전시키고 전 fixture 재생성이 필요한데, 요구 레벨 게이트가 이미 ①을 해결해 불필요하므로 기각.
- **지금 서버측 로드아웃 검증 추가** — PvE 는 3중 캡(ADR-0026·0027)이 보상 벡터를 이미 유계하고(착용 규칙 위반의 보상 이득 0), PvP 는 ADR-0028(공격측 로드아웃 권위 보류)에 요구 레벨 검증이 자연히 편입되므로, 신규 서버 표면 없이 클라 강제로 충분해 기각. PvE 정산에 검증을 붙이면 "PvE = 정산 요약만"(ADR-0026) 제출 표면을 확장하게 된다.

## Consequences

- ADR-0022 의 "기체 레벨은 잠그지 않는 순수 앵커" 는 **콘텐츠 접근(침략 단계 개방)** 에 대한 원칙으로 스코프가 명확해진다 — 요구 레벨은 **장비 파워 축에만 걸리는 직교 게이트**이며, 단계 개방은 여전히 클리어 기반(`max(10, 최고클리어+5)`)이다. 어느 개방 단계든 도전은 자유이되 자기 레벨을 넘는 장비를 휘두르지 못할 뿐이라, 두 축은 충돌하지 않는다.
- 기체 레벨은 한 기체에서 단조 증가한다(퇴역 = 새 기체) — 한번 착용한 장비가 부적격이 되는 일이 없어 자동 해제 로직이 필요 없고, 게이트는 저레벨·신규 세대의 **착용 시점에서만** 작동한다.
- ADR-0024 의 재성장 루프에 실체가 생긴다 — 신규 세대는 노말·매직으로 시작해 레벨을 올리며 레어(~중반)·유니크(~후반)를 순차 해금하고, 창고의 엔드게임 장비를 즉시 휘두르지 못한다.
- 요구 레벨은 저장하지 않고 아이템에서 파생한다(순수·결정론) — 세이브 스키마 변경이 없고, 서버가 필요 시 언제든 재도출할 수 있다.
- 장비가 유일하게 게이트 없던 축이라는 감사 결과가 확정된다 — 코어 모듈(방어/PvP)은 획득 희귀도·사용 횟수·래더 매칭이 공정성을 흡수하므로 게이트 대상이 아니고, 파워업은 런 내 획득이라 지속 파워를 만들지 않는다.
- 하네스 프리셋(하네스 프로필)이 저레벨 + 상위 장비를 주입하면 착용 UI 가 회색 처리하므로, 프리셋은 기체 레벨도 함께 올려 주입해야 한다.
- 요구 레벨 테이블 상수와 유니크별 저작 reqLevel 은 출시 전 밸런스 패스로 이월한다(2026-07-22 방침).
- 게이트 강제는 순수 술어(`canEquip`/`requiredLevel`, `src/items/requiredLevel.ts`) 1곳에 두고 **프로덕션 Pixi 장착 경로가 호출**한다 — 이 리포의 "테스트 그린인데 배선 없음" 결함군(`src/run/runConfig.ts:7-15`)을 막기 위해 grep 게이트·프로덕션 경로 통합 테스트로 배선을 정적 강제한다. 구현 계획: `.omc/plans/equipment-required-level.md`.

## 개정 2026-07-27 — 드랍처(침략 단계) 상한을 덧댄다

**바뀐 것:** 요구 레벨은 여전히 아이템 내재 파워(등급 + 어픽스 개수 / 유니크 저작값)에서 파생하되, **드랍처 상한**으로 낮춘다: `req = min(내재 파워 산식, stageLevelCap(item.source))`, `stageLevelCap = clamp(단계 × 5, 1, 100)`.

**왜:** 원안은 "요구 레벨을 드랍 단계에서 파생"을 기각했는데(위 Alternatives), 그 결과 **1단계 정예가 떨군 레어의 요구 레벨이 41** 이 되어 그 단계를 도는 Lv5 조종사에게는 영영 못 입는 전리품이 됐다(사용자 신고 2026-07-27: "기체 레벨보다 높은 아이템이 획득됨"). 획득 자체가 보상으로 읽히지 않으면 드랍은 노이즈다. 상한은 "**내가 딴 곳의 전리품은 그 단계를 도는 동안 입게 된다**"를 성립시킨다.

**대가(인지하고 받아들인다):** 원안이 막으려던 실패 모드 ①(저단계 럭키 드랍이 곧 최대 파워)이 **저단계 구간에서 되살아난다** — 어픽스 롤 값은 단계와 무관하게 flat 이므로(ADR-0022 완전 병렬) 1단계에서 나온 6어픽스 레어는 후반 레어와 같은 힘인데 이제 Lv5 에 입을 수 있다. 완화 요인은 저단계의 레어·유니크 확률이 매우 낮다는 것뿐이다(`src/sim/drops.ts` `stageRareMult`·`stageUniqueMult`). 이 잔여 위험은 **출시 전 밸런스 패스**에서 다룬다 — 선택지는 (a) `LEVEL_PER_STAGE` 기울기 조정, (b) 저단계 레어 확률 하향, (c) 어픽스 롤 값의 단계 스케일 도입(ADR-0022 반전이라 비용 큼).

**안 바뀐 것:** 순수·결정론(같은 아이템 → 같은 값, 서버 재도출 가능 — `item.source` 는 롤 시점에 박히는 저장 필드다), 세이브 스키마·상태 해시 불변, 클라 착용 시점 강제, 유니크 미저작 LOUD-FAIL. **행성 index 는 상한에 쓰지 않는다** — 6행성은 모드 성격이 다를 뿐 난이도 사다리가 아니고(아르케는 보스 설계도 고정 행성일 뿐), 난이도 축으로 쓰면 모드 취향이 곧 장비 제한이 된다.
