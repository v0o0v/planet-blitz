# ADR-0042 — 촉매 상점: 촉매 잔재로 닫은 자기 완결 경제

- 상태: 채택 (2026-07-31)
- 관련: ADR-0029(촉매 시스템 — 변칙 경보 대체) · ADR-0027(재화 서버 원장) ·
  ADR-0026(PvE 3중 캡) · ADR-0022(행성 차별화 — 특산의 행성 귀속)

## 맥락

촉매는 PvE 드랍으로만 얻는다. 이 설계는 `.omc/specs/deep-interview-catalyst-system.md`
에서 의도적으로 좁게 잡은 것이고, 거기에는 *"촉매 상점·합성 — 획득은 PvE 드랍 주축"* 이라고
상점이 **명시적 제외 항목**으로 적혀 있다.

운영해 보니 드랍 운의 분산이 그대로 노출된다. 파워축·보스 특산은 `dropWeight` 가 낮아 드물고,
반대로 안 쓰는 촉매는 계속 쌓인다. 플레이어에게 남는 조정 수단은 **분해**(촉매 → 크레딧) 하나뿐인데,
이건 촉매를 버리는 행위지 원하는 촉매에 가까워지는 행위가 아니다. 쌓인 재고를 원하는 종류로
바꿀 창구가 없다.

가장 쉬운 해법은 "크레딧으로 촉매를 판다"이지만, 이건 CONTEXT 의 계약
*"촉매 = 파밍이 다음 파밍을 키우는 닫힌 원환"* 을 깬다. 촉매에는 자원 보상축(`resource`)이 있어서,
크레딧으로 촉매를 살 수 있으면 **크레딧 → 자원축 촉매 → 자원 → 더 많은 크레딧** 의 자기 증식 고리가
생긴다. 3중 캡(ADR-0026)이 상한을 씌우긴 하지만, 캡이 방어선이라는 것 자체가 설계가 인플레
방향으로 기울었다는 뜻이다.

## 결정

**촉매 상점을 만들되, 촉매 전용 재화인 `촉매 잔재`로만 결제하게 해 경제를 촉매 안에 닫는다.**

1. **촉매 잔재** 신설 — 획득처는 촉매 **분해** 하나, 사용처는 촉매 상점 구매 하나.
2. **분해 보상 전환** — 촉매 분해는 이제 크레딧을 주지 않고 촉매 잔재만 준다.
   (장비 분해는 종전대로 크레딧·희귀 광물.)
3. **가격은 희소도 한 축에서 파생** — `구매가 = K / dropWeight`,
   `분해 환급 = r × 구매가`, 시작값 `r = 0.5`. 계수는 전부 `// BALANCE`.
4. **공용 30종만 판매** — 특산 촉매는 진열하지 않는다. 분해는 되지만 되살 수 없어
   특산 → 공용은 되돌릴 수 없는 일방 흐름이다.
5. **상시 전 카탈로그·해금 없음** — 로테이션 재고를 두지 않는다.
6. **구매 전용** — 상점에 파는 방향은 없다. 촉매를 재화로 바꾸는 행위는 종전대로 **분해**다.
7. **위치는 촉매 보관함 안의 탭** — 기지 시설을 늘리지 않는다(모듈 경제가 방어 사령부 안에
   사는 것과 같은 선례).

## 계약 세부

- **가격 정본은 TS, 서버에는 최종 정수 하나만 미러.** `catalyst_defs` 에 `buy_price` 정수
  컬럼을 더해 **48종 전부** 시드한다(특산도 가격을 갖는다 — 살 수 없는 정가표로만 존재하며
  환급액 산정 근거가 된다). 서버는 환급을 `floor(buy_price × r)` 로 계산한다. 산식을 SQL 에
  중복 구현하지 않으므로 반올림 차이로 클라 표시가와 서버 청구액이 어긋날 여지가 없다.
  `catalyst_defs` 는 상단에 동기화 의무 배너가 붙은 **수동 미러**라 `dropWeight`·`K` 튜닝이
  조용히 어긋날 수 있다. 그래서 **가격 48행 시드는 TS 카탈로그에서 생성**하고, vitest 가
  마이그레이션 파일을 읽어 TS 값과 대조한다 — 시드 갱신을 잊으면 CI 가 깨진다.
  (드리프트가 나면 화면 표시가와 서버 청구액이 갈라져 플레이어가 다른 값에 구매하게 된다.)
- **원장은 `profiles.catalyst_residue` 컬럼**(`>= 0` 체크). `grant_currency` 와 3중 캡
  파이프는 **거치지 않는다** — 외부 유입이 0이라 캡의 관심사가 아니고, 캡 산정·이상치
  플래깅 쿼리에 축을 늘리지 않기 위해서다. 잔재 변동은 분해·구매 두 RPC 트랜잭션 안에서만
  일어난다(차감과 적립이 같은 트랜잭션).
- **특산 촉매도 분해된다.** 다만 상점에 없으므로 되살 수 없다.
- **분해 조작 단위는 종류별 수량 지정** — 현행 `salvage_catalyst(catalyst_id, qty)` 를
  그대로 쓰고 화면에 수량 선택만 붙인다. 여러 종류 일괄 분해는 오조작 피해가 되돌릴 수 없어
  넣지 않는다.
- **잔재 잔고는 촉매 보관함·상점 화면에서만 표시**한다. 전 화면 상단 재화 칩(크레딧·광물)에는
  올리지 않는다 — 촉매 밖에서 쓸 수 없는 재화라 다른 화면에서는 소음이다.
- **온라인 전용** — 촉매 보유 정본이 서버라는 기존 계약을 그대로 따른다.

## 근거

- **총량이 늘지 않는다.** 잔재는 촉매를 없애야만 생기고, 스프레드(`r < 1`) 때문에 교환할수록
  촉매 총량은 오히려 줄어든다. 상점이 공급하는 것은 수량이 아니라 **종류 선택권**이다.
  그래서 이 경로는 3중 캡의 개연성 검증 대상이 아니고, 새 지급 캡·새 치팅 표면이 생기지 않는다.
- **인플레 고리가 구조적으로 불가능하다.** 잔재는 촉매 밖에서 가치가 0이라, 자원축 촉매로
  번 크레딧이 다시 촉매로 돌아오는 경로 자체가 없다.
- **비율이 기대값 중립이다.** 양쪽 모두 `dropWeight` 에서 파생하므로 "흔한 N개 → 귀한 1개"가
  드랍 확률 그대로 환산된다. 어떤 촉매를 녹여도 손해도 이득도 없고, 비용은 오직 스프레드다.
- **특산의 행성 귀속이 보존된다.** ADR-0022 의 종류 축 차별화는 "그 행성에 가야 얻는다"에
  기대고 있다. 특산을 팔면 톡사르를 한 번도 안 가고 톡사르 특산을 쥐게 된다.

## 대안과 기각 사유

| 대안 | 기각 사유 |
|---|---|
| 크레딧으로 결제 | 자원축 촉매를 통해 크레딧 → 자원 → 크레딧 자기 증식 고리가 생긴다. 3중 캡을 방어선으로 쓰게 되는 설계는 이미 기운 설계다 |
| 잔재를 런 드랍으로도 지급 | 촉매 총량이 늘어나 지급 캡·개연성 검증이 필요해지고, 촉매 드랍 자체의 의미가 희박해진다 |
| 침공·복수전 보상으로 지급 | 촉매는 "PvE 전용·침공 불개입"이 명시된 계약이다. PvP 가 PvE 파밍 파워를 공급하는 새 연결이 생긴다 |
| 분해 보상을 크레딧과 병행 | 촉매가 크레딧 파밍 수단으로 남아 salvage 축 캡 설계를 계속 져야 하고, "촉매 경제는 닫혀 있다"는 정체성이 흐려진다 |
| 분해 환급도 균일액 | 흔한↔귀한 교환이 희소도를 무시하게 돼, 파워축·보스 특산을 흔한 촉매로 양산할 수 있다 |
| 잔재 없이 촉매끼리 직접 교환(A n개 → B 1개) | 새 재화·컬럼·아이콘·가격 미러가 전부 불필요해 구현량이 절반이지만, **부분 누적**을 잃는다. 잔재는 안 쓰는 촉매를 보이는 대로 녹여 두었다가 나중에 원하는 것을 고를 수 있게 하는데, 직접 교환은 매번 "지금 n개를 내놓겠는가"를 강요해 잔동이 영영 버려진다 |
| 1시간 로테이션 재고 | 접속 동기는 생기지만, 총량이 안 늘고 가격이 이미 희소도를 반영하는 이상 재고 제한은 마찰만 남긴다. 로테이션 상점은 모듈 경제가 이미 담당한다 |
| 플레이어 간 거래소 | 계정 간 재화 이전 경로가 생겨 3중 캡(정직 파밍 속도 상한)이 무효화되고, 봇·복수 계정·현금거래 방어가 통째로 새 과제가 된다 |

## 결과

- **좋은 점**: 드랍 운 구제 창구가 생기고, 안 쓰는 촉매가 자원이 된다. 새 지급 캡·새 치팅
  표면이 0이라 서버 방어 설계가 늘지 않는다. 밸런스 손잡이가 `K`·`r` 둘뿐이다.
- **비용**: 재화가 셋으로 늘어(크레딧·희귀 광물·촉매 잔재) 원장·HUD·i18n 에 축이 하나 더
  붙는다. 촉매 분해로 들어오던 크레딧 수입이 사라져 크레딧 유입이 그만큼 준다 —
  미출시라 마이그레이션 부담은 없으나, 크레딧 밸런스 패스에서 이 항을 빼고 다시 봐야 한다.
- **부수**: `salvage_catalyst` 의 보상 경로가 바뀌므로 SQL 상수 `SALVAGE_CREDITS_PER_UNIT`
  와 `CAP_SALVAGE_CREDITS` 의 촉매 몫이 의미를 잃는다(장비 분해 몫만 남는다).
- **되돌리기**: 잔재를 크레딧으로 되돌리려면 원장 잔량 보상 처리가 필요하다. 미출시 동안은
  싸고, 출시 후에는 비싸다.
