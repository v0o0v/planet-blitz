# 조우는 행성 모드와 무관하게 반드시 도달 가능하다

ADR-0033 이 조우 프레임워크를 세울 때 워프 유형(보물 격실)은 **뱀서류 모드 한정**으로 게이트했고("v1 워프 detour 는 뱀서류 모드 한정으로 게이트돼 있다"), 나머지 5개 모드는 다운스트림 과제로 남겼다. 그 뒤 실측해 보니 게이트의 전제가 대부분 사실이 아니었고, 게이트를 통과한 비-워프 유형조차 강제 스크롤 모드에서는 **1.5~2.7초 만에 화면 밖으로 흘러가 사실상 도달 불가**였다. 즉 "6개 모드가 각자 정체성에 맞는 변형을 갖는다"(ADR-0033)는 계약이 5개 모드에서 사실상 "조우 없음"으로 구현돼 있었다.

## 배경 — 실측

**① `allowWarp` 게이트가 실제로 막고 있던 것은 3블록뿐이었다.**

`createWorld` 의 `allowWarp` 게이트는 스크롤(블록격파·레이싱)·수축·추격·오염 모드에서 워프 유형을 후보에서 통째로 뺐다. 근거는 "워프가 플레이어를 창 밖 12만 유닛으로 옮기는데 모드 규칙이 전부 좌표에 기댄다"였다. 실제 차단 지점은 `stepPlayer` 꼬리의 경계 블록 **3개**뿐이다.

- `clampToWindow` — 12만 유닛 밖으로 워프한 플레이어를 **첫 틱에** 창 안으로 도로 끌어당긴다(워프 자체가 무효화).
- 블록격파 압사 · 레이싱 후방압박 — 창 경계 기준 누적 피해.
- `shrinkOutOfBounds` — 원점에서 12만이면 안전 반경 밖이므로 detour 45초 내내 **매 틱 피해** → 사망.

이 3블록이 방 안까지 따라온 이유는 `stepDetour` 가 `stepPlayer` 를 의존성 주입으로 받아 그대로 호출하기 때문이다. 그리고 **추격·오염에는 차단 메커니즘이 아예 없었다** — 두 모드는 창도 안전 반경도 갖지 않는데 이유 없이 같은 게이트에 묶여 있었다.

**② 스크롤 모드에서 조우 오브젝트가 순식간에 도달 불가가 되는 라이브 버그.**

조우 오브젝트는 `player.x + ENCOUNTER_SPAWN_OFFSET(540), player.y` 에 뜨는 **정적 엔티티**다. 강제 스크롤 창은 12 유닛/틱으로 전진하고(`scrollStep(100)`, `INVASION_SCROLL_SPEED = 12`), 창 반폭은 960(`VIEW_WIDTH/2`)·반높이는 540(`VIEW_HEIGHT/2`) 이다. 오브젝트는 창 기준으로 뒤로 흘러간다.

- 블록격파(전진 −Y): 최대 (540 + 540) / 12 = **90틱 ≈ 1.5초**
- 레이싱(전진 +X): 최대 (960 + 960) / 12 = **160틱 ≈ 2.7초**

상호작용 반경은 320 이다. 즉 오스카 제단·봉인 수호자의 봉인이 크라스·아르케에서 사실상 도달 불가였다. 게이트를 통과한 유형마저 도달 불가였으므로, 게이트만 걷어내는 것으로는 문제가 닫히지 않는다.

## 결정

**조우 오브젝트는 행성 모드와 무관하게 반드시 도달 가능해야 한다.** 네 규칙으로 강제한다.

1. **경계 블록 추출.** 위 경계 블록 3개를 `stepPlayer` 꼬리에서 `stepWorld` 의 `stepPlayer(...)` 호출 **직후**로 옮긴다. detour 분기는 그 줄에 닿기 전에 return 하므로 detour 중에는 모드 경계 규칙이 **아예 실행되지 않는다** — 플래그·모드 분기 없이 **구조적으로** 제외된다(ADR-0033 의 "산발 게이트 금지" 규율 준수). 두 지점 사이에 코드가 없어 실행 순서가 동일하므로 **기존 런 해시는 바이트 불변**이다.
2. **게이트 제거.** `allowWarp` 를 없애 워프 유형이 모든 모드에서 후보에 든다. 롤 구조(등장 chance → 유형 가중 → 스폰 틱, 3회 소비)는 그대로라 **RNG 소비량 불변**이다.
3. **창 고정.** 근접이 필요한 시설 3종(보물 격실 포탈 · 오스카 제단 · 봉인 수호자의 봉인)은 스폰 시 창/안전 반경 안으로 클램프하고, 강제 스크롤 모드에서는 **매 틱 창 상대 좌표를 유지**해 화면상 정지해 보이게 한다. 무시해도 계속 따라오며, 해제 수단은 기존 거부 입력(`SPECIAL_ENCOUNTER_DECLINE`, Q키)뿐이다.
4. **전방 스폰.** 기록 파편우의 파편은 강제 스크롤 모드에서 적 스폰과 **같은 관용구**(`BLOCKBREAK_SPAWN_AHEAD` / `RACING_SPAWN_AHEAD`)로 진행 방향 전방에 뿌려 플레이어 쪽으로 흘러오게 한다. **파편은 창에 고정하지 않는다** — 수집물이 화면에 붙어 따라다니면 수집이라는 행위 자체가 사라진다. 시설 3종과 처리가 다른 것이 의도다.

## Considered Options

- **모드별 조우 변형을 각각 설계**(ADR-0033 이 예고한 per-mode 다운스트림) — 6종 × 유형별 변형은 표면이 크고, 그 사이 5개 모드는 계속 "조우 없음"으로 남는다. 먼저 **도달 가능성**이라는 하한을 전 모드에 깔고 변형은 그 위에 얹기로 했다.
- **`allowWarp` 게이트만 제거** — ②의 흘러감 버그가 남아 스크롤 두 모드에서는 여전히 도달 불가. 기각.
- **모드별 예외 플래그로 경계 규칙을 끄기**(detour 중 `skipClamp` 등) — 산발 게이트가 늘어나 ADR-0033 의 규율에 반하고, 플래그를 안 켠 신규 모드에서 조용히 재발한다. 호출 지점 이동(구조적 제외)을 택했다.
- **조우 오브젝트를 이동체로 만들기**(플레이어를 추적) — 신규 이동 로직·해시 필드가 필요하고, 정적 세트피스라는 조우의 시각적 정체성이 흐려진다. 창 상대 좌표 유지가 더 싸고 결정론적이다.
- **파편도 창에 고정** — 수집물이 화면에 붙어 따라다녀 "먹으러 간다"가 사라진다. 기각(규칙 4).

## Consequences

### 제약 — 왜 이렇게밖에 못 했는가

- **신규 `EntityKind` 금지**(`KIND_CODE` append-only 해시 계약) → 봉인은 `encounterPortal` kind 를 재사용하고, 유형 구분은 `encounterRuntime.type` 으로 한다(렌더도 같은 축으로 갈린다).
- **`EncounterRuntime` 신규 필드 금지**(해시 조건부 꼬리 폴드 계약) → 유형별 상태는 기존 `rt.aux` 정수 패킹으로 얹는다.
- **RNG 소비 0**, `Math.random` / `Date.now` 금지, 삼각함수는 `src/sim/math.js` 의 `cos` / `sin` 만 쓴다.
- **뱀서류·추격·오염은 창도 안전 반경도 없으므로 신규 경로를 한 줄도 타지 않는다** — 이것이 이 세 모드의 골든 불변 근거다.

### 밸런스로 넘긴 것

- 경계 블록을 `stepPlayer` 밖으로 꺼내면 detour 45초 동안 **수축 반경 밖 피해 · 블록격파 압사 · 레이싱 후방압박이 멈춘다** → "위험할 때 포탈로 피신"이 가능해진다. 런당 조우 최대 1회 + 방 안 경비가 있어 무한 악용은 아니지만, 의도된 쉘터인지 완화 대상인지는 **출시 전 밸런스 패스에서 판단**한다. 이 ADR 에는 **기록만 하고 구현은 하지 않았다**(ADR-0033 의 "detour 쉘터 효과" 항목과 같은 성격의 유예).
- 여유 마진·오프셋 등 이번에 도입한 신규 상수는 전부 placeholder 이며 `TODO(밸런스)` 로 표시했다.

### 검증

- 자동 테스트 `tests/encounterModeMatrix.test.ts` 가 6개 모드 전부에서 조우 도달 가능성을 커버한다.
- **육안(브라우저) 확인은 이번 범위 밖**이다. 시설 3종이 스크롤 화면에서 "정지해 보이는지"는 사람 눈으로 한 번 확인해야 하며, 하네스 플레이테스트 큐로 넘긴다.
