# ADR-0039 — 같은 유니크의 중복 장착은 **장착 시점에서 차단**한다

- 상태: 채택 (2026-07-28)
- 관련: ADR-0030(장비 요구 레벨 게이트 — 같은 "착용 시점 순수 술어" 양식) · ADR-0005(sim/render 분리)

> ⚠️ 번호 주의: 이 저장소에는 `0029`·`0034` 가 각각 두 개씩 있다(과거 병렬 레인 충돌).
> 다음 ADR 은 **0040** 부터 잡되, 먼저 `ls docs/adr/` 로 중복 여부를 확인할 것.

## 맥락

`computeLoadoutStats`(`src/items/loadout.ts`)는 장착 아이템의 유니크 효과를 `uniqueMask` 에
**비트 OR** 로 합친다. 따라서 같은 `uniqueId` 를 두 칸에 꽂으면 **같은 비트를 두 번 세우는 것**이라
두 번째 사본의 유니크 효과가 통째로 무효가 된다. 어픽스는 정상 합산되므로 화면에 아무 경고도
없고, 플레이어는 칸 하나를 낭비했다는 사실을 알 수 없다.

재현 가능한 슬롯은 저작 유니크가 2종 이상인 슬롯이다(현행 main 6 · sub 2 · armor 2 · module 2).
그중 `module` 은 장착 칸이 2개(`module0`/`module1`)라 가장 쉽게 재현된다.

발견 경위: 2026-07-27 밸런싱 레인에서 표준 장비 세트를 결정론 조립하다가 드러났다. 조립기
(`src/bench/standardBuild.ts` `rollForSlot`)는 배정된 유니크 id 집합을 넘겨 **자체 회피**했지만,
**실제 게임의 장착 경로에는 결함이 그대로 남아 있었다.**

## 결정

**장착 게이트에서 차단한다.** `uniqueMask` 의 의미(비트 OR)는 건드리지 않는다.

| 갈래 | 결정 |
|---|---|
| 처방 | 이미 같은 `uniqueId` 를 장착 중이면 **장착 불가** |
| 강제 지점 | 순수 술어 `duplicateUniqueSlot`(`src/items/uniqueEquip.ts`) + 프로덕션 격납고 `equip()` |
| 사용자 피드백 | **힌트 문구 표시**(`inv.err.duplicateUnique`) — 무음 거부 금지 |
| 교체(같은 유니크로 갈아끼우기) | **허용** — 대상 칸은 판정에서 제외 |
| 기존 세이브의 중복 장착 | **유지**(자동 해제 안 함) + 스탯 표에 "중복 — 효과 없음" 표기 |
| sim · 상태 해시 · 세이브 스키마 | **불변** |

### 왜 "중첩 허용"이 아닌가

두 번째 사본에 **대체 효과**를 주는(중첩 허용) 설계도 가능하다. 기각한 이유:

- 유니크 효과는 전부 sim 의 **비트 분기**다. 중첩 규칙을 두면 저작 유니크 **15종 각각에** 규칙을
  정의해야 하고, 규칙마다 `src/sim/**` 수정이 따라온다 → 골든 재생성 + `verify-invasion` Edge
  Function 재배포가 **확정 비용**으로 붙는다.
- 얻는 것은 "같은 유니크를 두 개 주웠다"라는 드문 상황의 표현력뿐이다. 비용/편익이 맞지 않는다.
- 차단은 순수 아이템·UI 계층에서 끝난다(sim 무관). 나중에 중첩을 원하면 그때 게이트를 풀면 되고,
  그 전까지는 "칸이 조용히 낭비되는" 상태가 사라진다.

### 왜 기존 세이브를 자동 해제하지 않는가

1. **데이터 유실 위험** — 해제는 아이템을 인벤토리로 되돌리는 조작인데 인벤토리는 상한
   (`INVENTORY_CAP`)이 있다. 가득 찬 상태로 로드하면 갈 곳이 없어 아이템을 버리거나 상한을 넘겨야
   한다. 사용자가 지시하지 않은 파괴적 변경이다.
2. **손해가 없다** — 중복 사본도 어픽스는 정상 합산된다. 무효인 것은 유니크 효과뿐이라 그대로
   둔다고 게이트 도입 전보다 나빠지지 않는다.
3. **되돌릴 방법이 있다** — 게이트는 새 장착만 막고 **해제는 막지 않는다.** 그러라고 격납고
   스탯 표가 무효 사본을 "중복 — 효과 없음"으로 명시한다.

정책 요약: **막되 빼앗지 않는다.** 근거는 `src/items/uniqueEquip.ts` 의
`LEGACY_DUPLICATE_POLICY` 주석에 코드 옆에도 남겼다.

## 귀결

- 신규 순수 모듈 `src/items/uniqueEquip.ts` — `duplicateUniqueSlot`(차단 술어) ·
  `redundantUniqueIndices`(무효 사본 표시). `src/sim/**` 미의존(ADR-0030 와 같은 결정론 경계).
- 격납고 `equip()` 이 요구 레벨 게이트 **다음에** 이 술어를 호출하고, 거부 시 힌트를 세운다.
- 회귀 스위트 `tests/uniqueEquip.test.ts` 4층: ①재현(두 칸 = 한 칸) ②순수 술어 ③grep 배선 게이트
  ④실제 `HangarScreen.equip()` 통합. 게이트를 임시로 끈 상태에서 ④가 실패하는 것을 확인했다.
- 표준 장비 조립기의 회피 로직은 그대로 둔다(성격이 다르다 — 그쪽은 "후보를 버리고 다시 굴린다").
  두 축이 같은 불변식("장착 표에 같은 `uniqueId` 둘 없음")을 다른 방식으로 지킨다.
