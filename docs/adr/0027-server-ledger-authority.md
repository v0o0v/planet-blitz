# 재화·기체 소유는 서버 원장이 정본이다

profiles.save는 클라이언트 통짜 업로드(last-write-wins)라 credits·희귀 광물·기체·장비·스킬 투자를 임의로 위조할 수 있고, 서버 RPC 12곳이 그 값을 정본으로 읽어 왔다. 리플레이 검증을 아무리 조여도 이 경로가 열려 있으면 무의미하다 — 특히 위조 기체로 침공하면 리플레이가 내적으로 일관되어 전수 검증을 통과하고 래더가 오염된다(verifyInvasionCore에 문서화됐던 공격자 로드아웃 잔여 신뢰).

재화(크레딧·희귀 광물)와 기체 소유(기체·장비·스킬 투자)를 save에서 분리해 **서버 전용 원장**으로 옮긴다. 획득은 정산·드랍 RPC가, 소비는 건조·강화·구매 RPC가 원장에서 직접 처리하고, verify-invasion은 공격자 로드아웃을 원장과 대조한다. 지급은 즉시다 — 검증 후 지급은 ADR-0005가 기각한 비용 구조라 채택하지 않고, PvE 지급의 상한은 3중 캡(ADR-0026)이 담당한다. save에는 방어 배치·설정·진행 플래그 등 전투력에 권위가 없는 상태만 남는다.

## Consequences

- 서버 RPC 12곳의 `save->>'credits'`/`'minerals'` 파싱이 원장 참조로 바뀐다 — 기존 유저 save 값은 1회 이관하며, 미출시 상태라 기존 값의 위조 리스크는 무시한다
- 재화·소유 변동이 전부 서버 RPC 경유가 되므로 클라이언트는 오프라인에서 이를 확정할 수 없다 — 로컬 표시는 낙관적 사본이고 정본은 서버다
- 공격자 로드아웃 위조 경로가 닫혀, 래더 오염 벡터는 침공 리플레이 위조(전수 검증이 차단)만 남는다
- 기체 획득·강화 경로 전부(건조·장비 장착 해제·스킬 투자·분해·리롤)가 RPC화되는 큰 마이그레이션이다 — 재화 이관과 한 결의로 묶어 한 번에 끝내는 것이 이중 마이그레이션보다 싸다는 판단
- PvE 정산 요약의 보상 재계산(ADR-0026)과 한 쌍으로 동작한다 — 원장 없는 캡, 캡 없는 원장 모두 반쪽이다
