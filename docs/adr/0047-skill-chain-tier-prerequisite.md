# ADR-0047 — 스킬 사슬: 계열 안 같은 스탯의 티어 선행 조건

- 상태: 채택 (2026-08-03)
- 관련: ADR-0019(기체 타입 고유 트리) · ADR-0005(sim 결정론·리플레이 해시) ·
  ADR-0027(재화 서버 원장 권위) · ADR-0028(공격자 로드아웃 권위 보류) ·
  ADR-0041(액티브 스킬 계열 게이트)

## 맥락

스킬트리의 base 노드에는 **선행 조건이 하나도 없다**. 유일한 게이트는 캡스톤
(계열 base 누적 ≥ 40, `data/skills.ts`)뿐이다. 그래서 만렙 파일럿의 ~99포인트는
63칸 어디에나 자유롭게 흩뿌릴 수 있고, 트리의 티어 구조가 **투자 순서에 아무 제약도
주지 않는다** — 5티어는 사실상 "숫자가 더 큰 칸"의 라벨이었다.

디아블로2 계열 트리의 긴장(깊이 투자를 강제해 빌드가 무엇을 포기했는지 드러남)이
빠져 있고, 티어 시너지(`SYNERGY_PER_LOWER_POINT`)만으로는 그 압력이 약하다.

동시에 손대기 어려운 이유가 셋 있다.

1. `skillInvest` 의 **flat 인덱스는 삼중 계약**이다 — 리플레이 해시 폴드 · 파생 스탯 ·
   파워업 RNG 슬라이스(`data/ships/types.ts` 헤더). 노드를 재배치하면 셋이 조용히 깨진다.
2. `computeSkillStats` 는 클라이언트와 검증 Edge Function 이 **공유하는 순수 함수**다.
   여기에 규칙을 넣으면 서버 재배포 없이는 두 쪽이 갈린다.
3. 노드 데이터는 기체 7종 × 3계열이고, 스탯 분포가 기체마다 다르다
   (브루저 `rangeFlat` 1노드 · 해츨링 `maxHpFlat` 11노드).

## 결정

**한 계열 안에서 같은 스탯을 올리는 노드들을 "사슬"로 보고, 사슬 안에서 더 낮은
티어를 전부 max 해야 그 위에 투자할 수 있게 한다.**

| 갈래 | 결정 | 기각한 대안 |
|---|---|---|
| 사슬의 축 | **(계열, 스탯) 자동 파생** | 노드에 `chainId` 명시 저작 · 열 인덱스 = 사슬 |
| 사슬의 범위 | **계열을 넘지 않는다** | 스탯만으로 전 트리 관통 |
| 게이트 강도 | **더 낮은 티어 전부 max** | 전부 1포인트 이상 · 바로 아랫 티어만 max |
| 적용 지점 | **투자 시점(UI·저장 경로)만** | `computeSkillStats` 파생 시점 · sim/서버 판정 |
| 캡스톤 | **사슬에서 제외**, 기존 누적 40 게이트 유지 | 캡스톤도 사슬 말단으로 편입 |
| 기존 세이브 | **마이그레이션에서 무료 전액 리스펙** | 그랜드파더 · 위반 노드만 부분 회수 |
| 화면 | **배치 불변**, 팝업 잠긴 행에 부족한 선행 노드 표기 | 팝업을 티어 격자로 재배치 · 표시 없음 |

### 사슬의 정확한 규칙

- 사슬 = 한 계열의 base 노드 중 `stat` 이 같은 것들, 티어 오름차순.
- 노드 N 에 투자하려면 **같은 사슬에서 티어가 N 보다 낮은 노드가 전부 max** 여야 한다.
- 티어에 구멍이 있으면 그냥 건너뛴다(사슬에 없는 티어는 조건이 아니다).
- 한 티어에 같은 스탯 노드가 둘이면 **둘 다** max 여야 한다
  (화력 t0 의 집중 사격 + 정밀 조준).
- 노드가 하나뿐인 사슬은 선행 조건 없이 열린다(화력 `rangeFlat`).
- 티어 0 에는 선행 조건이 없다.

## 왜 자동 파생인가

명시 저작은 사슬 길이를 고르게 맞출 수 있지만 21개 트리를 손으로 적어야 하고,
새 기체를 추가할 때마다 저작 부채가 붙는다. 자동 파생은 데이터 수정 0줄이고 신규
기체가 규칙을 공짜로 물려받는다.

대가는 **게이트 강도가 칸마다 다르다**는 것이다 — 화력 damagePct t1 은 8포인트
선투자를 요구하고, `rangeFlat` 은 아무 조건도 없다. 이 요철을 결함이 아니라
**의도된 결**로 받는다: 주력 스탯일수록 사슬이 길고, 곁가지 스탯은 값싸게 집어간다.

## 왜 파생이 아니라 투자 시점인가

이 규칙은 **치팅 방어가 아니다.** 서버는 오늘도 `skillInvest` 의 합법성을 검증하지
않는다(ADR-0028 이 로드아웃 권위를 명시적으로 보류했고, 리플레이는 제출된 벡터를
그대로 접는다). 파생 시점 게이트를 넣어도 위조 창구는 그대로 열려 있고, 대신
`computeSkillStats` 와 EF 재배포·해시 재검증 부담만 진다.

투자 시점으로 한정하면 **파생 스탯·리플레이 해시·파워업 RNG 슬라이스가 한 비트도
안 움직인다.** 벤치의 `standardBuild` 앞채우기는 flat 순서 = 티어 오름차순이라 항상
합법이므로 골든도 영향받지 않는다.

## 왜 강제 리스펙인가

선행 조건이 여태 없었으므로 기존 벡터에는 위반 투자가 얼마든지 있다. 그대로 두면
규칙이 불변식이 아니게 되고 — 더 나쁘게는 — **리스펙 한 번이 되돌릴 수 없는 손실이
된다**(전액 초기화 뒤에는 규칙 때문에 원래 배치로 못 돌아간다). 그 함정을 남기느니
마이그레이션에서 한 번 털고 간다. 포인트는 전액 환급이고 리스펙 비용은 없다.
장비·진행도는 건드리지 않는다.

## 결과

- `data/**` 노드 데이터 수정 0줄, flat 인덱스 불변.
- `computeSkillStats`·sim·Edge Function 수정 0줄.
- 리스펙은 이미 전액 초기화라(`applyRespecRefund`) 부분 회수로 위반을 만들 수 없다.
- 액티브 강화 파워업(`bumpActiveTree`)은 런 중 `config.skillInvest` **사본**의
  t0 칸을 올릴 뿐 프로필에 남지 않고, t0 는 선행 조건이 없어 무관하다.
- 저티어를 강제로 채우게 되므로 **초·중반 빌드가 균질해진다.** 이건 밸런스 축이고,
  수치 튜닝은 출시 직전 일괄 방침 그대로 미룬다.
- 하네스 `preset('maxed')` 는 전 노드 max 라 여전히 합법이다.
