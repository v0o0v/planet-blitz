# 변칙 경보 폐지, 촉매 시스템으로 대체

시드 랜덤 제안형 변칙 경보(수락/거부, ~25%, 효과 3종)는 "공짜 랜덤"이라 능동 소비 동기를 만들지 못했다. POE 스캐럽 문법의 **촉매**로 대체한다: PvE 런 드랍(엘리트·보스)으로 얻는 소모품을 성계 지도 출격 전에 주입해 그 런 1회에 난이도 페널티+보상 부스트를 함께 얹는다. 구 변칙 3종 효과(중력 폭풍·군체 대발생·암흑 성운)는 승계하지 않고 카탈로그를 백지 설계한다 — 공용 30종(전 행성 드랍, 수치·구성 변형만) + 행성당 특산 3종(그 행성 독점 드랍·**그 행성 런 전용 주입**, 효과는 그 행성 특성 기반). 2026-07-24 그릴 세션에서 확정.

## 결정 사항

- **적용 단위**: 런 1회 소모형. 행성 지속형·맵 아이템화 기각(행성 = 영구 파밍 스팟 전제 보존).
- **효과 모델**: 종류당 고정 효과(스캐럽식). 랜덤 롤형(오브식) 기각 — 런이 ~2분인 루프에 리롤 마찰이 크고, 롤 시점의 시드 권위 문제가 추가된다.
- **스택**: 다중 주입 + 같은 종류 중복 스택 허용. 위험-보상 동봉이라 스택할수록 페널티도 같이 쌓여 자기 밸런싱된다(슬롯 수·배율 곡선은 출시 전 밸런스 패스).
- **방향성**: 전 촉매 페널티+보상 동봉. 순수 버프형 기각 — 위험 없는 버프는 "바르는 게 무조건 이득"이라 결정이 아니라 세금이 된다.
- **등급**: 무등급 플랫. 4등급 준용 기각 — 48종 × 4등급 매트릭스는 통제 불능이고, 세기 축은 스택 수가 이미 담당한다.
- **무대**: PvE 침략 전용. 침공(PvP)·래더·리플레이 검증 계약 불개입.
- **특산의 경계**: 특산 촉매는 출신 행성 전용이다. 초안의 "모드 요소 타 행성 이식"은 기각(2026-07-24 번복) — 행성 모드의 행성 귀속 원칙(ADR-0021)에 예외를 만들지 않는다.

## 서버 권위: 시작 시 소모 (코어 모듈 문법의 의도적 예외)

촉매 보유 수량의 정본은 서버 원장(ADR-0027)이고, 주입분은 **런 시작 시** 서버에서 차감한다. 코어 모듈의 "사용 횟수는 결과 확정 시에만 차감" 문법과 정반대이므로 근거를 남긴다:

- 촉매는 **보상 배율**을 올리는 소모품이라, 정산 시 소모로 하면 "발랐다" 신고의 진위를 정산 시점에 검증해야 한다. 시작 시 소모는 서버가 적용 목록을 시작에 이미 확정하므로 거짓 신고 창구 자체가 없다.
- 코어 모듈은 방어자(피동측) 자산이라 공격자가 런을 버릴 때 방어자가 손해 보면 안 되지만, 촉매는 주입자 본인의 능동 선택이라 POE 맵 소모와 같은 자기 책임 문법이 성립한다.
- 수반 결과(수용됨): 촉매 런의 시작은 온라인 전용이 되고, 중도 포기·크래시 시 촉매는 소실된다. 무촉매 런의 시작은 종전대로 서버 왕복 없음.

기각 대안 — 정산 확정 시 소모(포기 시 보존, 오프라인 시작 유지): 코어 모듈과 문법 통일이라는 장점이 있었으나, 정산 검증 복잡도와 거짓 신고 방어 비용이 더 크다고 판단.

## 귀결(Consequences)

### hashWorld 1회 포맷 범프 + verify-invasion 컷오버 48h 창

anomaly 를 걷어내면서 `hashWorld` 의 **무조건 중간 폴드 4개**(`anomalyRng.getState()`·`anomaly.kind`·`anomaly.active`·`config.anomalyAccepted`)가 제거됐다. 이 폴드들은 조건부 꼬리가 아니라 항상 실행되던 중간 폴드였으므로, 제거는 **침공을 포함한 전 런**의 per-tick 해시를 한 칸씩 앞당기는 **1회 포맷 범프**다(촉매는 대신 `echo` 폴드 뒤 **조건부 꼬리** — 주입 촉매가 있을 때만 접히므로 무촉매 런·침공 런은 바이트 불변). 흡수 절차: **전 결정론 골든 재생성 + `verify-invasion` Edge Function 재배포**(신 클라와 같은 sim 소스로 재번들).

**컷오버 오탐 창(≤48h)**: 침공 리플레이 보존 TTL 이 48시간이다(마이그레이션 `supabase/migrations/20260726000100_invasion_replay_ttl.sql`). 따라서 신 `verify-invasion` EF 를 배포하는 순간, 그 직전까지 **구 클라(구 해시 포맷)로 제출돼 아직 검증 대기 중인 in-flight 침공 리플레이**는 신 EF 의 재시뮬레이션 해시와 불일치해 **오거부**될 수 있다. 이 창은 리플레이 TTL 로 상계되어 배포 후 최대 48h 안에 자연 소멸한다(만료된 리플레이는 재검증 대상에서 빠짐). 무촉매 PvE 정산·재화 경로에는 영향이 없다(PvE 는 리플레이 재검증을 이미 폐기 — ADR-0026). 배포 시 신 클라·신 EF·골든을 한 릴리스로 함께 내보내 창을 최소화한다.

### 촉매 런 시작은 온라인 전용

서버 시작 시 소모 결정의 직접 귀결(위 §서버 권위 참조): 촉매를 실은 출격은 `consume_catalysts` 왕복이 성공해야 시작되므로 온라인 전용이고, 실패/오프라인이면 출격 폴백 모달([재시도]/[촉매 빼고 출격])로 무촉매 시작을 보존한다. 무촉매 런의 시작은 종전대로 서버 왕복이 없다.
