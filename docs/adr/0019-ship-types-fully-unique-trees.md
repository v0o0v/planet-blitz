# 기체 타입은 완전 고유 스킬트리 — 공유 골격 없이 소수 로스터로 시작

단일 기체 전제를 버리고 LoL 챔피언식 기체 타입 다양화를 도입하면서, 타입 간 차별화 수준을 결정해야 했다. 결정(2026-07-20 그릴링): **기체 타입마다 3계열 스킬트리 전체와 시그니처 패시브(상시 발동 고유 효과)·기본 스탯 보정·외형을 완전 고유로 만들고, 대신 1차 로스터를 4~5종으로 작게 시작한다. 장비 8슬롯 호환·이동·판정점·조작감은 전 타입 공통이다.** 첫 기체는 기본 타입 자동 지급, 퇴역 시 다음 기체는 로스터 전체에서 자유 선택한다(해금 조건 없음).

대안은 ① 공유 트리+타입별 캡스톤만 고유(제작 최소), ② 3계열 중 1계열만 고유(절충), ③ 로스터 점진 해금이었다. ①②는 "결국 다 비슷하다"가 금방 드러나 타입 선택·분석의 재미라는 도입 목적 자체를 죽인다. ③(점진 해금)은 장기 목표를 만들지만 퇴역이라는 드문 이벤트의 선택 폭을 좁히므로 전체 개방을 택했다(사용자 명시 선택). 장비 호환을 공통으로 못박은 것은 파밍 경제가 기체 세대를 관통해야 "이 유니크를 다음 기체에도 쓴다"는 장기 동기가 유지되기 때문이다.

## Consequences

- 타입 1종 추가 = 3계열 트리(현행 63노드 규모)+시그니처 패시브+외형 아트 일습의 제작 약속이다 — 로스터 확장은 콘텐츠 마일스톤 단위로만 가능
- 현행 단일 공유 트리(data/skills.ts)는 "기본 타입의 트리"로 재편되고, 트리 데이터는 타입별 데이터로 일반화해야 한다
- 파워업·장비 파생 파이프라인(computeSkillStats→파생 블록 합산)은 공유 인프라로 재사용한다 — 트리 데이터만 타입별로 갈린다
- 수호 기체 스냅샷·전투력 점수·계보는 타입과 직교한다 — 퇴역한 타입이 무엇이든 동일 생애주기를 따르되, 수호 기체 AI 행동은 타입 시그니처를 반영할 수 있다(확장 여지)
- 밸런스 면적이 타입 수에 비례해 늘어난다 — 타입×장비×어픽스 조합 검증이 필요, 1차 4~5종 상한은 이 비용의 통제 장치다
