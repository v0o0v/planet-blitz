# 행성 환경 테마 확산 Phase 2 (2026-07-29)

카르곤 하나뿐이던 배경 테마를 **행성 5개 + 침공 3레이어**로 확산하고, 엔티티 접지 그림자와
계약 봉인까지 마친 레인의 기록. 수치와 결정의 정본은 코드 주석과 테스트에 있고, 여기에는
**코드만 봐서는 복원되지 않는 것**만 남긴다.

#199 침공 · #202 계약 봉인 · #201 접지 그림자. main `f5cd43e`, vitest 220파일 4,632건.

## 병렬 6레인이 충돌 0 이었던 이유는 스캐폴딩이다

레인이 소유하는 파일을 `themes/<planet>/` 와 `scripts/tileset-profiles/<planet>.mjs` 로 **완전히
분리**할 수 있었던 것은, 유일한 공유 지점인 `ENV_THEMES` 배열 등록을 **선행 커밋으로 끝냈기**
때문이다(PR#194). 레인마다 한 줄씩 더하게 뒀으면 6개 브랜치가 정확히 같은 줄에서 충돌한다.
6브랜치 병합에서 실제로 충돌이 0 이었다.

부수로 드러난 것: 레이어 두 곳의 "담당 테마가 없는 행성에서는 스스로 꺼진다" 테스트가 행성
인덱스를 **리터럴(1·5)** 로 들고 있어 등록과 동시에 깨졌다. **리터럴이면 그 행성에 테마가 생기는
순간 단언의 의미가 "레이어가 꺼진다"에서 "아직 아무도 안 만들었다"로 뒤집힌다.** 등록된 담당
행성에서 파생한 빈 인덱스를 써야 의미가 유지된다.

## 뮤테이션 검증이 계약의 구멍 세 개를 찾았다 (이번 레인의 최대 수확)

각 레인에 "값을 일부러 깨고 테스트가 실제로 빨개지는지 확인해라"를 필수 산출물로 요구했더니,
**서로 모르는 레인들이 독립적으로 같은 구멍을 짚었다.** 전부 PR#202 에서 잠갔다.

| 구멍 | 발견 | 실체 |
|---|---|---|
| `referenceBackdrop` 이 실제 지형과 맞는지 아무도 안 본다 | 니플헤임·크라스 **독립 2회** | 검증기는 "입자가 *선언된* 배경과 다른가"만 본다. "선언된 배경이 그 행성의 실제 화면인가"는 무검사 |
| 안전 색상 창이 **적 스프라이트 몸통색**을 안 본다 | 톡사르·베르단 | 위험색이 적탄+아군 표식뿐. **톡사르 적 몸통(281.6°)이 톡사르 골짜기(280.2~305.0°) 안**이다 |
| 행성별 광원 서사를 못 박는 게 없다 | 니플헤임 | 태양을 발밑으로 뒤집어도 전 테스트 그린 |

### 봉인하며 얻은 판단 두 개

- **적 몸통 분리를 색상각으로 재면 안 된다.** 그렇게 재면 **카르곤이 0.4° 로 즉시 탈락**한다
  (용암 `#e83a17` ↔ 돌격병 몸통 `#584541` — 색조는 겹치지만 명도·채도가 완전히 달라 화면에서
  헷갈릴 수 없다). 아르케는 채도 0.04~0.08 이라 색상각 자체가 무의미하다. **ΔRGB 거리**가 실제
  위장에 가깝다. 하한 30 은 화면 판정기의 "구분 불가" 거리 70 의 절반(35, 현재 최솟값과 동일)
  바로 아래 자리다.
- **`referenceBackdrop` 은 밝기와 색을 나눠 재야 한다.** 통짜 ΔRGB 로 재면 니플헤임이 114 로
  튀는데 그건 결함이 아니라 저작 판단이다(흰 입자에게 가혹한 기준은 어두운 암반이 아니라 밝은
  설면). 밝기에는 판단이 섞이고 **색 방향은 자산의 사실**이다. 그리고 **어두운 암석 행성 넷은
  서로 3~8 밖에 안 떨어져 있어, 그 넷을 구분한다고 주장하는 문턱은 항진이다** — 이 축이 잡는
  것은 "눈 행성에 암반색" 같은 계열 오류다.

## 측정 도구가 존재하지 않는 회귀를 만들었다

성능 벤치에서 `env.disable()`/`env.solo()` 를 반복한 **뒤에** 찍은 카르곤 컷이 **균일 단색**
(전 픽셀 L=12.15)이 되어, 기준선 대비 `mean |ΔRGB| 48` 짜리 대규모 회귀로 보였다. sim 해시는
4시드 전부 동일한데 픽셀만 전면 변경 — 정확히 "렌더 회귀"의 서명이다.

**갈라낸 것은 `tone` 의 `spread 0.00`** 이었다. 델타 하나만 봤으면 없는 결함을 쫓았다.
→ `BASELINE.md` 의 캡처 조건에 6번으로 추가했다: **벤치·솔로 조작 뒤에는 새로고침하고 촬영해라.**

벤치 이전에 찍은 깨끗한 컷으로 다시 재니 **카르곤 픽셀 회귀는 정확히 0**이었다(`mean 0.00`,
변화 블록 0.00% — 비트 동일). 침공 레인이 `main.ts`·`autotile.ts` 를 건드렸는데도 그렇다.

## 행성별로 실제로 값을 치른 것

- **아르케만 게이트에 걸렸다.** 시드 3 에서 차저 위장 2.21%(warn, 카르곤 현재 실측 0.53%).
  충돌 지점은 면 전체가 아니라 **베벨 립**(가장 밝은 픽셀)이었고 ΔRGB 59 였다. 저채도 회색으로는
  거리를 못 벌린다 — **채도를 올리지 않고 분리를 얻는 유일한 축이 채널 기울기 방향**이라 지각을
  따뜻한 쪽에서 차가운 쪽으로 뒤집고 `crustL` 47→42 로 내렸다. 2.21% → 0.93%.
- **위장의 실체는 적탄이 아니라 적 스프라이트였다**(베르단·톡사르·크라스 전부 같은 결론).
  크라스는 적 4종 몸통색이 **전부 동일**해서 위험한 것이 색상각이 아니라 중간 밝기의 따뜻한
  색이었고, G 채널을 100 아래로 묶어 거리의 절반 이상을 확보했다.
- **니플헤임은 밝은 바닥이라 규율이 뒤집힌다.** 넓은 가산(`plume`)은 흰색 포화로 화면을 뭉개므로
  통째로 뺐고, 곱연산으로 예산을 옮겼다(곱연산 화면차는 `바닥밝기 × α × (1−배수)` 라 설면에서
  카르곤 암부의 3배로 듣는다). 지형광 국소 기여가 카르곤의 절반인 것은 바닥이 아니라 **재배치**다.
- **크라스가 생성기 불변식의 사각을 찾았다**: 실루엣은 전 타일이 공유하는 고정 함수라, "타일 안
  위치마다 상부로 분류될 확률"이 치우치면 그대로 64px 명암 무늬가 된다. **I1~I4 는 균일 타일
  내부만 보므로 이걸 못 잡는다.**

## 침공 — sim 은 정말로 안 움직였고 장애물은 stage 깊이뿐이었다

`invasionBackdrop` 을 배경에서 **페이즈 전환 베일**로 재정의했다. 하네스 실측으로 확인한 동작:
평상시 알파 **0**(아래 Wang 지형이 그대로 보인다) → 전환 시 0 → 0.97 → 0 으로 45틱, 그 절정
뒤에 타일셋·테마를 **1회만** 교체(변화 순간에 갈면 교체가 맨눈에 보이고, 매 프레임 갈면 뷰포트가
매 프레임 재타일된다). 실측 stage 순서: `autotile(3) → env.floor(4) → 베일(5) → 엔티티(6)` —
베일이 엔티티 **아래**라 절정에도 함선·탄이 안 가려진다.

침공 테마는 **합성 행성 인덱스 6·7·8**(`INVASION_ENV_PLANET_BASE + phase`)로 붙였다. 침공 런의
`config.planet` 이 항상 0 이라 행성 축을 그대로 쓰면 "침공인데 카르곤 화면"이 된다.

`tests/encounterHashInvariance.test.ts` 골든 파일 수정 0 으로 바이트 불변이 확인됐다.

## 성능 — 무엇이 비싼지 오해하지 마라

`sim 틱 + 렌더 1프레임`의 벽시계 ms 로 재고, **드리프트를 지우려면 교차 측정**해야 한다
(단발 측정에서는 부하에 따라 절대값이 2~3배 흔들렸다).

- 침공은 문제가 아니다 — 카르곤 PvE 와 동급이다.
- **니플헤임이 카르곤의 2.75배**로 나왔지만 **환경 레이어를 통째로 꺼도 격차가 그대로**였다
  (4.75 vs 12.82ms, 타일 수·텍스처 크기·스프라이트 수 동일). 니플헤임은 **추격 모드**
  (`visionRadius 1400`)라 시야 오버레이 비용이 원래 있다.
- 이번 작업이 더한 몫은 전 행성 **0.5~1.4ms**.

## 접지 그림자

방향이 테마의 공유 `light` 에서 **파생**된다. 6행성 광원 서사가 실제로 갈려 있어
(카르곤·톡사르·침공 L3 = 아래, 나머지 여섯 = 위) 그림자 부호도 갈린다. 이걸 잠근 단언이
**부호 다양성 자체**(`Set{-1,1}`)를 재는 것이라, 오프셋을 테마 무관 상수로 되돌리면 즉시
`expected Set{1} to deeply equal Set{-1,1}` 로 걸린다.

합성은 곱연산이다. "어두운 바닥에서 화면차가 작아지는" 성질이 여기서는 **이득**이다 — 어두운
행성일수록 적 실루엣이 먹힐 위험이 큰데 곱연산이 스스로 약해진다. 하네스 실측 국소 기여
카르곤 6.05 / 니플헤임 8.20 / 톡사르 10.70 / 크라스 4.22 로, 한 알파가 6행성 전부에서 성립한다.

**형제 컨테이너라 부모 `destroy` 로 회수되지 않는다**(Pixi v8 `Sprite.addChild` deprecate 회피).
킬 루프·reset·destroy·테마 전환 네 경로가 명시 회수하고, **디졸브 경로**(스프라이트가 잔류)도
즉시 회수한다 — 안 하면 사라진 실체의 그림자만 바닥에 얼어붙는다.
