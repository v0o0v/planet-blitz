## Goal

런 승리에서 드물게 얻는 **의뢰서**를 신설한다. 의뢰서는 무대(행성 목록·침략 단계)·주문·보상이
전부 적혀 온 소모품이며, 수락하면 그것만 나오는 전용 단일 런이 열린다. 주문 4종(연쇄 원정·
제약 계약·현상금 표적·정예 소집령)이 각각 다른 종류의 재미를 만들고, 지시 계급 4단(정기·우선·
특급·최종)이 가치와 여정 길이를 함께 정한다.

## Constraints

- 의뢰서의 내용을 굴리는 것도 보유분의 정본도 **서버 원장**이다 — 획득·출격은 온라인 전용
- **출격 시 소모**하며 실패하면 소멸한다. 런 중 수거 전리품은 기존 규율대로 전량 보존
- 보상은 **경제·수집 축에만** 실린다. 새 재화를 만들지 않는다. 확정 금액이라 **행성 인기 배율 밖**
- 의뢰 런에는 **촉매를 주입할 수 없고**, 중반 격전도 조우도 들어오지 않는다
- 의뢰 런의 승리는 **최고 클리어 단계를 갱신하지 않는다**
- 의뢰 런은 다시 의뢰서를 낳지 않는다
- 보관 상한 있음, 실시간 만료 없음
- 구간 경계는 **월드 재생성**이며, 승계는 플레이어 상태뿐이고 재생성 자체가 결정론이어야 한다
- 제약 계약은 **위반이 원천 불가능한 축만** 쓴다 — sim 에 감시 카운터·위반 처리기를 두지 않는다
- 긴 의뢰 런이 EF CPU 예산(한도 2초) 안에 들어와야 한다 — 최종 지시의 구간 수 상한은 여기서 역산

## Non-Goals

- 호송·납품 주문 (1차 범위 제외)
- 결과축 제약(피격 N회 이하·제한 시간)과 조작축 제약(대시 금지)
- 런 밖에서 이어지는 표적 추적(의뢰서 상태 갱신)
- 의뢰 전용 재화·전용 상점
- 의뢰 런의 재도전·보상 열화·부분 지급
- 계급별 이원 검증(고계급만 리플레이 제출)

## Acceptance Criteria

- [ ] 보스 처치 승리 정산에서 낮은 확률로 의뢰서가 서버 원장에 발령된다. 의뢰 런 정산은 발령하지 않는다
- [ ] 지시 수신소에서 보유 의뢰서의 무대·주문·보상·계급을 읽고 출격할 수 있다. 보관 상한 초과 시 새 발령이 들어오지 않는다
- [ ] 출격 시 서버 원장에서 의뢰서가 차감된다. 런 실패 후 그 의뢰서가 목록에 남아 있지 않다
- [ ] 연쇄 원정 런에서 구간이 넘어갈 때 행성 모드가 바뀌고, 플레이어 HP·런 내 성장·수거 전리품이 승계되며, 이전 구간의 적·탄·지형·모드 런타임이 남아 있지 않다
- [ ] 같은 리플레이를 서버가 재실행하면 구간 경계의 월드 재생성을 포함해 해시 스트림이 일치한다
- [ ] 의뢰 런은 리플레이를 제출하고 일반 PvE 런은 제출하지 않는다
- [ ] 서버가 리플레이 `config` 와 의뢰서를 대조해 제약 계약 준수를 판정한다. 위반 loadout 으로 만든 런은 거부된다
- [ ] 정예 소집령 런에서 잡몹이 0 기 스폰되고, 경험치 젬이 0 개 드랍되며, 파워업 3택이 한 번도 열리지 않는다
- [ ] 정예 소집령에서 처치가 늦으면 다음 정예가 겹쳐 내려온다(고정 타이머·enrage 없음)
- [ ] 현상금 표적이 도주하면 진행 게이트 충족 여부와 무관하게 그 구간이 종료된다
- [ ] 마지막 구간에서도 표적을 못 잡으면 의뢰 실패로 확정된다
- [ ] 의뢰 런 승리 후에도 그 행성·단계의 최고 클리어 단계가 변하지 않는다
- [ ] 의뢰 런에 촉매를 주입할 수 없고, 중반 격전·조우가 등장하지 않는다
- [ ] 의뢰 보상에 행성 인기 배율이 곱해지지 않는다

## Assumptions Exposed & Resolved

| Assumption | Challenge | Resolution |
|------------|-----------|------------|
| 3행성 연속은 여러 런이다 | 침공 3레이어가 이미 단일 런으로 다구간을 한다 | 단일 런. 정산·리플레이 1건 |
| 행성 모드는 런 내내 고정이다 | 고정이면 연쇄 원정이 그냥 긴 런이다 | 구간마다 모드 교체(ADR-0046) |
| 모드 교체 = 런타임 스왑 | config 는 33곳이 매 틱 읽는 불변 값이고 런타임은 createWorld 1회 생성 | 월드 재생성. 플레이어 상태만 승계 |
| PvE 는 정산 요약만 내면 된다(ADR-0026) | 3중 캡은 수량 축이라 확정 유니크를 못 막는다 | 의뢰 런만 리플레이 제출(ADR-0044) |
| 실패 시 소멸은 너무 가혹하다 | 12분 런을 통째로 잃는 것이 정말 옳은가(Contrarian) | 유지. 그 무게가 의뢰의 정체 |
| 제약 위반 시 즉시 런 종료가 필요하다 | 장비축·성장축만 쓰면 위반이 원천 불가능하다(Simplifier) | 위반 처리기 통째로 삭제 |
| 잡몹 없으면 젬을 정예가 대신 떨궈야 한다 | 그러면 "정예가 많은 평범한 런"이 된다 | 성장 0 그대로. 빌드 시험대(ADR-0043) |
| 의뢰서 등급 = 아이템 4등급 재사용 | 의뢰서는 물건이 아니라 문서다 | 전용 계급 4단(정기·우선·특급·최종) |
| 표적은 런 밖으로 도주해 추적이 이어진다 | "출격 시 소모·실패 시 소멸"과 양립 불가 | 한 런 안에서 도주. 도주 = 구간 종료 |

## Technical Context

- `src/run/runConfig.ts` — 런 입력 조립의 **단일 정본**. 신규 런 입력(의뢰서 식별자·구간 목록)은
  반드시 여기에만 추가한다. `tests/shipIntegration.test.ts` 의 grep 게이트가 `main.ts` 재중복을 막는다
- `src/sim/world.ts` — `state.config.planetMode` 를 33곳이 매 틱 읽는다. 모드별 런타임은
  `createWorld`(1089-1231)에서 1회 생성. 이것이 월드 재생성 구조를 택한 근거
- `src/sim/planetMode.ts` — `PLANET_MODE` 는 리플레이 wire/hash 값이라 append-only
- `src/save/settlement.ts:177-178` — 현재 `result.victory` 를 그대로 믿어 클리어를 기록
  (`:177` 가드 · `:178` `recordPlanetClear` 호출. `:175-176` 은 주석 줄이다). ADR-0044 의 동기
- `data/boss.ts` / `data/bosses/*` — 보스는 3페이즈 + HP 임계 + 공격 프리미티브 목록의 데이터 행.
  의뢰 보스 추가는 원칙적으로 데이터 추가이되, 신규 프리미티브가 필요하면 sim 확장
- `src/sim/replay.ts` · verify-invasion EF — 침공이 쓰는 재실행 경로. 의뢰 런이 이것을 공유한다
