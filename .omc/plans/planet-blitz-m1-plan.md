- 상태: **pending approval** (실행 승인 대기)

## 1. 요구사항 요약

M1 = 플레이 가능한 전투 프로토타입 1개 런. 범위(GDD §13):

- 결정론 시뮬 코어 (⚠️ 첫 코드부터 ADR-0005 규율 — 사후 도입 불가)
- 아레나·조작(WASD+마우스, 대시)·자동 공격(주무기 발칸 1종)·탄막·충돌
- 적 4종(역할 4슬롯 — 카르곤 계열, 홈월드 튜토리얼 재사용 대상) + 보스 1종(3페이즈+과열 창+탄 소거)
- 웨이브 시스템(랜덤 카드 조합+구간 예산표) + 런 내 성장(3택 파워업 축소판)
- 재미 요소: 젬 콤보 · 보급선 습격 · 격추 유머 연출
- **재미 게이트**: 내부 테스터 5인 중 4인 "한 판 더" + 런 완주율 60%+

비범위(M1에서 제외): 장비·드랍(M2), 스킬트리(M3), Supabase·PvP(M4), 퇴역·계보(M5), 사운드(폴리시 단계 📝).

## 2. 기술 기반 결정 (기확정)

- TypeScript(strict) + PixiJS v8, 번들러 Vite, RPG UI는 DOM 오버레이 (ADR-0001)
- 시뮬/렌더 완전 분리: 시뮬 코어는 순수 TS 모듈(플랫폼 독립, 추후 Edge Function에서 재실행) (ADR-0005)
- 고정 타임스텝(제안: 60Hz 시뮬 틱), 시드 RNG 전용, `Math.random`/`Date.now` 금지
- 1920×1080 기준 레터박스, 픽셀아트 정수 배율
- 에셋: 픽셀랩포지(pixellab-forge 스킬, 재사용 캐시 워크플로) PNG → 스프라이트시트

## 3. 프로젝트 구조 (제안)

```
/
├── src/
│   ├── sim/            # 결정론 시뮬 코어 (PixiJS import 금지 — lint로 강제)
│   │   ├── rng.ts      # 시드 RNG (xoshiro128** 또는 mulberry32)
│   │   ├── world.ts    # 고정 타임스텝 상태 머신
│   │   ├── entities/   # 기체·적·탄·젬·보급선
│   │   ├── patterns/   # 패턴 컴포넌트 엔진 (발사체×궤적×타이밍)
│   │   ├── waves.ts    # 웨이브 카드 풀 + 예산표 + 시드 추첨
│   │   ├── replay.ts   # 입력로그 기록·재생, 상태 해시
│   │   └── collision.ts# 공간 해시 그리드
│   ├── render/         # PixiJS 계층 (시뮬 상태 → 화면, 보간)
│   ├── input/          # 키보드·마우스 → 시뮬 입력 프레임
│   ├── ui/             # DOM 오버레이 (HUD·파워업 3택·정산)
│   └── main.ts
├── tests/              # vitest — 결정론·시뮬 단위 테스트
├── assets/
└── data/               # 적·패턴·웨이브·파워업 정의 (JSON/TS 데이터)
```

## 4. 구현 단계 (태스크 분해)

### Phase 0 — 리포·스캐폴드
1. `git init` + GitHub 리포 생성(`v0o0v/planet-blitz` 제안, 사용자 확인 필요) + `feat/m1-combat-prototype` 브랜치 — 전역 규칙(브랜치→PR) 적용
2. Vite + TS(strict) + PixiJS v8 + vitest + ESLint 스캐폴드. `src/sim/`에서 `pixi.js`·`Math.random`·`Date.now` import/사용 금지 lint 규칙
3. `.claude/launch.json` (Vite dev 서버) — 브라우저 프리뷰 검증용

### Phase 1 — 결정론 코어 (모든 것의 기반)
4. 시드 RNG + 고정 타임스텝 월드 루프 + 입력 프레임 포맷
5. 리플레이 기록·재생 + 상태 해시 → **결정론 테스트**: 같은 시드+입력로그 2회 실행 시 틱별 해시 100% 일치 (vitest)
6. 렌더 어댑터: 시뮬 상태 스냅샷 → PixiJS 표시(보간 포함), 레터박스 스케일링, ParticleContainer 탄막 렌더

### Phase 2 — 코어 게임플레이
7. 기체: 이동(WASD+마우스 겸용)·대시(쿨다운+무적프레임)·HP·피격 무적
8. 자동 공격: 최근접 조준 + 주무기 발칸(연사) — 파워업 증폭 파라미터 구조 포함
9. 충돌: 공간 해시(기체·적·탄·젬), 탄막 가독성 규칙 적용(아웃라인+화이트 코어 스프라이트)
10. 적 4종(카르곤 계열, 패턴 스펙 초안): 파쇄차(돌격)·박격포(사수, 착탄 예고 장판)·용암샘(특수, 용암 기둥 라인)·수리드론(지원, 회복 빔) — 패턴 컴포넌트 엔진 위 데이터 정의
11. 웨이브: 6구간 × 카드 풀 8종 시드 추첨 + 구간 예산표(적 12→44, 동시 탄 300→2,000)

### Phase 3 — 런 루프 완성
12. 경험치 젬 + 자석 수거 + **젬 콤보**(연속 수집 배율 최대 x1.5)
13. 레벨업 3택 파워업 — M1 축소 풀 8종(발칸 파생 4 + 이동/대시 파생 2 + 범용 2), DOM 오버레이 UI (일시정지 없이 시뮬 틱 정지 방식 — 결정론 유지: 선택도 입력로그에 기록)
14. **보급선 습격**: 20초 제한 횡단 보급선, 격추 시 보상(M1은 자원 플레이스홀더)
15. 보스 1종(카르곤 "용암 요새 전차"): 3페이즈(HP 100/70/35%)·페이즈 전환 탄 소거+2초 연출·과열 창(시전 후 5초 피해 2배, 시각 표시)
16. **격추 유머 연출**(사출·낙하산) + 사망/클리어 → 정산 화면(임시: 획득 경험치·처치 수·시드 표시)
17. HUD: HP·경험치 바·타이머·콤보 배율·보스 HP 바

### Phase 4 — 에셋·게이트
18. 픽셀랩포지 에셋: 기체 48px(8방향 불필요 — 탑다운 회전), 적 4종 32px, 보스 128px, 탄막·젬·이펙트 시트, 카르곤 화산 배경 타일 — 캐시 조회 후 miss만 일괄 생성
19. 성능 벤치 씬: 탄 2,000발+적 200 스폰 고정 시나리오 → 60fps 검증 (실패 시 ParticleContainer/오브젝트 풀 튜닝)
20. 재미 게이트: 테스터 5인 플레이 → "한 판 더" 4/5 + 완주율 60% 측정. 미달 시 파워업 체감·웨이브 리듬부터 튜닝 반복
21. PR 생성 → 머지 (전역 git 규칙)

## 5. 수용 기준 (테스트 가능)

- [ ] `vitest` 결정론 테스트: 동일 [시드+입력로그] 2회 실행의 틱별 상태 해시 완전 일치
- [ ] `src/sim/`에 PixiJS·`Math.random`·`Date.now` 참조 0건 (lint CI 통과)
- [ ] 리플레이 파일 재생으로 라이브 플레이와 동일한 정산 결과 재현
- [ ] 벤치 씬에서 탄 2,000발 동시 표시 중 60fps (기준 데스크톱)
- [ ] 런 1회 = 5~8분: 6구간 웨이브 → 보스 → 정산까지 무크래시 완주 가능
- [ ] 적 4종이 역할 4슬롯(돌격·사수·특수·지원)에 대응하고 각각 고유 패턴 발사
- [ ] 보스: 페이즈 전환 시 화면 탄 전체 소거, 과열 창 5초간 받는 피해 2배 로그 확인
- [ ] 젬 콤보 배율이 UI에 표시되고 수집 중단 시 리셋
- [ ] 보급선이 등장 20초 후 이탈하며, 격추 시 보상 지급
- [ ] 웨이브 조합이 시드에 따라 달라지되 구간별 동시 탄 상한을 초과하지 않음
- [ ] 재미 게이트: 테스터 5인 중 4인 "한 판 더" + 완주율 60%+ 기록

## 6. 리스크와 완화

| 리스크 | 완화 |
|---|---|
| 부동소수점 결정론 — 클라이언트(브라우저 V8)와 Edge Function(Deno V8) 간 연산 차이 | 같은 V8 계열이라 기본 연산은 동일. `Math.sin/cos` 등 초월함수는 엔진별 차이 가능 → 시뮬 코어에서 자체 근사 테이블 또는 고정 소수점 각도 테이블 사용. M1에서 결정론 테스트를 CI에 넣어 조기 검출 |
| 탄 2,000발 성능 미달 | ParticleContainer + 오브젝트 풀 + 충돌 공간 해시를 처음부터 적용. 벤치 씬을 Phase 1에서 미리 만들어 조기 측정 |
| 파워업 3택 UI(DOM)와 시뮬 정지의 결정론 충돌 | 선택 이벤트를 입력로그의 특수 프레임으로 기록 — 리플레이 시 동일 틱에 재적용 |
| 픽셀랩포지 생성 비용·품질 편차 | pixellab 스킬의 캐시 워크플로 준수(재사용 우선, miss 일괄 생성). 임시 도형 플레이스홀더로 게임플레이 먼저 검증 후 에셋 교체 |
| 재미 게이트 미달로 M1 장기화 | 게이트 실패 시 튜닝 대상 우선순위 고정: ①파워업 체감 ②웨이브 리듬 ③적 탄속/밀도. 3회 반복 후에도 미달이면 설계 회귀 논의 |
