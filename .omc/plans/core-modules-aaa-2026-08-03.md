2. **품질 티어를 런타임 수렴 상태로 판단하지 마라**(`getActiveTier()` 단독 사용 금지).
3. **띠를 겹쳐 그라디언트를 근사하지 마라.** 램프는 폭 1px 캔버스에 픽셀로 굽고 `linear` 로

5. 자산은 **덧붙임이지 전제가 아니다**. **이 레인은 새 자산을 만들지 않는다.**
6. 캔버스 없는 환경(vitest)에서 `Text.width`·`document.createElement`·`ColorMatrixFilter`·
   `FillGradient`(**`new Text` 시점**에 던진다)가 전부 던진다. 관용구는
   `typeof document === 'undefined' || typeof document.createElement !== 'function'`.
   ⚠️ **캔버스 굽기 함수에만** 붙인다 — DOM 조회(`hudEl`)에 붙이면 HUD 숨김이 죽는다.
7. `npx tsc --noEmit` 0 · `npx eslint src tests --max-warnings 0`.

## 1. 이 화면 고유의 판단 여섯

### ① 창을 뚫는가 → **뚫지 않는다.** 보여줄 피사체가 없다

형제 화면 여섯의 결론은 "창은 배경이 보이는 구멍이 아니라 **무언가를 보여주는 자리**"였다.
뚫은 둘은 **피사체가 있었다** — 챔피언 선택은 전용 함선 원화, 방어 사령부는
`createWorld(invasion3)` 실제 정지 렌더. 뚫었다 뺀 넷(촉매 보관함·예비역 로스터·연구소·정제소)은
초점 피사체가 없었다.

코어 모듈은 후자다. 모듈은 **아이콘도 3D 도 없는 순수 수치 인스턴스**(등급·잔여 횟수·어픽스
문자열)다. 창을 뚫으면 확대된 UI 조각조차 못 세우고 배경만 보이는 구멍이 된다.
→ 패널 3장 전부 `variant: 'slab'`, 배경 `windows: []`.

### ② **정보 밀도가 목적인 화면이다** → 3열을 유지한다

격납고 계약 §0-bis-3 의 판단. 이 화면의 기본 동작은 **세 목록을 오가며 비교하는 것**이다:
슬롯(어디에 꽂나) ↔ 보관함(무엇을 꽂나) ↔ 상점(무엇을 더 사나). 보관 게이지 20칸이 그 셋을
동시에 제약한다(만석이면 구매·합성 결과가 막힌다). 한 열이라도 접으면 조작이 왕복이 된다.

→ 열 셋을 **한 번에 세워 두고 값만 갱신**한다. 탭은 두지 않는다(탭 줄 자체가 이 화면에는
빈 자리다 — 전환할 축이 없다).

### ③ 하단 [기지로 돌아가기] 버튼은 **없앤다**

헤더 ✕ 와 같은 일(close)을 두 번 제공하고 있었다. 형제 화면 여섯은 전부 헤더 ✕ 하나만 쓴다.
사문화되는 문구 키 `mod.back` 은 **카탈로그에 남긴다**(방어 사령부 §1-③ 선례 — 지우면 무관한
i18n 단언이 흔들린다).

### ④ 보관 게이지·합성 바를 **보관함 패널에서 하단 액션 띠로 내린다**

옛 구현은 게이지(라벨+미터)와 합성 바(버튼 2개)를 보관함 패널 **콘텐츠 상자 맨 위**에 얹어
목록 시작 y 를 118 → 약 230 으로 밀었다. 그런데 둘 다 보관함 한 열의 성질이 아니라
**화면 전역 제약**이다 — 만석이면 상점 [구매]도 막히고, 합성 대상은 보관함 목록에서 고르지만
결과는 게이지와 슬롯 양쪽을 움직인다.

하단 띠로 내리면 ⓐ보관함 목록이 상자 세로를 전부 쓰고 ⓑ하단 띠에 빈 자리가 없어진다.

| 자리 | 내용 |
| --- | --- |
| 왼쪽 위 줄 | 보관 게이지 라벨 + 미터(만석이면 붉게) |
| 왼쪽 아래 줄 | 상태 토스트(구매·합성·분해·장착 결과) |
| 오른쪽 안쪽(w 200) | 비합성 = 합성 안내 문구 · 합성 중 = `[취소]` |
| 오른쪽 끝(w 300) | 비합성 = `[합성 시작]` · 합성 중 = `[합성 확정 (n/3)]` |

⚠️ 버튼 자리는 **모드와 무관하게 고정 폭**이다. 모드마다 폭이 달라지면 오른쪽 끝 등호가 깨지고
버튼이 화면에서 좌우로 튄다. 비합성 모드의 w200 자리는 문구가 쓰므로 빈 자리가 아니다.

### ⑤ 분해에 **확인 팝업**을 붙인다

분해는 되돌릴 수 없이 모듈을 없애고 크레딧으로 바꾼다. 옛 구현은 행의 [분해] 한 번으로
즉시 실행됐고, 그 버튼은 [장착] 바로 옆 108px 이었다. 이 화면에서 유일하게 퇴로가 없는 조작이라
확인을 한 겹 둔다(방어 사령부 `confirmTest` 선례 · 확정 버튼 톤 `red`).

⚠️ **`makeModal`(나무)은 고치지 않는다** — 다른 화면 다섯이 쓴다. 화면 파일 안에 시네마틱 팝업을
만들고 `modal.ts` 헤더 실측 규칙 3종을 승계한다: ①암막 불투명 ②암막이 이벤트를 먹음
③패널 안쪽 탭은 전파 차단.

### ⑥ 빈 자리를 남기지 않는다

- 슬롯 열은 **원리적으로 2행뿐**이다(`MODULE_EQUIP_SLOTS = 2`). 행이 남는 세로를 나눠 갖고
  (`fillRowHeights`, 상한 {@link SLOT_ROW_MAX_H}) 그래도 남으면 **파낸 챔버**로 그 자리에
  이름을 준다 — 자동 발동·소모품이라는 두 사실이 거기 앉는다.
- 상점은 재고가 4~6칸(`MODULE_SHOP_NORMAL_RANGE [3,4]` + `MODULE_SHOP_MAGIC_RANGE [1,2]`)이라
  역시 남는다 → 같은 처방(꼬리 챔버에 "매일 새 재고").
- 로딩·오프라인·조회 실패·빈 보관함은 **빈 패널로 두지 않는다** — 패널 상자를 통째로
  `recessedWell` 로 그리고 그 안에서 안내한다(정제소 §6-bis-2 처방).
- ⚠️ 조회 실패 챔버에는 `[다시 시도]` 가 함께 앉는다(기존 계약 — `mod.load.retry`).

## 2. 레이아웃 (디자인 스페이스 1920×1080)

여백 어휘(32 / 28 / 20 / 하단 28)와 헤더 높이 104 는 형제 화면과 **같은 값**이다.

| 요소 | x | y | w | h |
| --- | --- | --- | --- | --- |
| 헤더 밴드(배경 노출) | 0 | 0 | 1920 | 104 |
| 슬롯 패널 | 32 | 124 | 460 | 848 |
| 보관함 패널 | 520 | 124 | 800 | 848 |
| 상점 패널 | 1348 | 124 | 540 | 848 |
| 하단 액션 띠 | 32 | 988 | 1856 | 64 |

전부 파생이다 — `PANEL_Y = GEAR_BAND_H + 4`(**헤더 104 아래가 아니라 톱니 밴드 120 아래**:
슬롯 패널이 x32 라 톱니와 가로로 겹친다) · `FOOT_Y = 1080 − 28 − 64` ·
`PANEL_H = FOOT_Y − 16 − PANEL_Y` · `SHOP_X = INV_X + INV_W + 28` ·
`SHOP_W = 1920 − 32 − SHOP_X`. 우변 `1348 + 540 = 1888 = 1920 − 32` ✓

헤더 컨트롤(전부 y 26 · h 52) — **정제소·방어 사령부와 같은 x**:

| 컨트롤 | x | w |
| --- | --- | --- |
| (각인 제목 = 중앙 960, 대역 ±280) | — | — |
| 크레딧 칩 | 1628 | 190 |
| 닫기 ✕ | 1832 | 56 |

- 광물 칩(x 1424)은 **두지 않는다** — 이 화면의 재화는 크레딧뿐이다(구매·분해). 헤더 밴드는
  배경이 그대로 보이는 띠라 칩이 하나여도 빈 자리가 아니다.
- 좌상단 x<120 · y<120 은 **설정 톱니 예약 밴드**. 헤더 좌측은 비워 둔다(테스트로 잠근다).
- 제목 대역 680..1240 과 첫 칩 1628 사이 388 — 중앙 정렬 Text 는 사각형이 없어 겹침 테스트가
  못 잡으므로 `TITLE_BAND_HALF_W` 로 대역을 못 박는다(연구소에서 제목이 실제로 겹쳤다).

### 패널 안(패널 로컬, 제목 띠 있는 슬래브: box = x24 · y68 · w W−48 · h H−92)

- 슬롯 box = 412×756 · 보관함 box = 752×756 · 상점 box = 492×756. bottom = 824.
- 슬롯 행 폭 412, `[비우기]` 116 → 글자 폭 `412 − 116 − 32 − 12 = 252`.
- 보관함 행 폭 752, `[장착]`·`[분해]` 각 116 → 글자 폭 `752 − 232 − 32 − 12 = 476`.
- 상점 행은 **버튼이 문구 아래**다(열이 좁아 옆에 붙이면 어픽스 폭이 눌려 읽히지 않는다 —
  관제탑 교훈, 옛 구현 승계).
- 마스크 높이는 `clampToRows` 로 행 경계에 떨군다(반토막 행 금지 — 기존 계약 유지).

### 팝업 — 높이를 **내용에서 역산**한다

| 팝업 | 폭 | 높이 | 역산식 |
| --- | --- | --- | --- |
| 분해 확인 | 760 | 264 | `68 + (본문 96 + 20 + 버튼 56) + 24` |

`68 = TITLE_BAND_H(52) + CONTENT_GAP(16)`, `24 = EDGE_PAD`. 버려지는 세로가 0 이고
단위 테스트가 등호로 잠근다.
암막 알파는 **0.99** 에서 시작하되 **실화면으로 확인**한다(예비역 0.92 · 챔피언 0.96 ·
연구소 0.98 · 방어 사령부 0.99 — 뒤 화면 밝기에 따라 다르다. 여기는 밝은 슬래브 **셋**이다).

## 4. 재렌더 규율

현재 구현은 `render()` 가 루트를 통째로 지우고 다시 그린다. 그대로 두면 슬롯 클릭 한 번,
합성 토글 한 번마다 **배경과 석재 패널 3장이 다시 구워진다**.

- `buildChrome()` — 배경 · 패널 3장 · 헤더 · 하단 띠 그릇은 **한 번만**. 자산 도착 시 1회 재건.
- `syncValues()` — 재화 칩 · 보관 게이지 · 상태 문구 · 하단 버튼 활성/라벨.
- `renderSlots()` / `renderInventory()` / `renderShop()` — 각자 host 안에서만.
- `renderModal()` — 팝업 host 안에서만.
- `update(dt)`: **`main.ts` 가 매 프레임 부른다**(`modulesScreen.update(frame)` 를
  `defenseCommand.update(frame)` 바로 옆에 배선). 숨겨져 있으면 즉시 반환.
  ⚠️ 연구소가 이 배선을 빠뜨려 배경·패널 연출이 통째로 멈춘 적이 있다.

⚠️ **크롬(헤더·하단 띠)은 패널보다 뒤에 붙여 위로 올린다.** Pixi v8 은 자식을 역순으로 훑다가
픽셀에 걸리면 거기서 멈추고 가장 가까운 상호작용 조상을 반환한다 — 석재 패널이 접지 그림자를
텍스처에 구워 자기 사각보다 30px 가까이 번지므로, **비상호작용 그림자도 클릭을 훔친다**
(PR#252 에서 "탭 아래 절반이 클릭 안 됨"으로 실제 신고됐다). 조립 순서를 소스에서 잠근다.

## 5. 기능 불변식 — 깨면 즉시 불합격

1. **진입 규약을 한 줄도 건드리지 않는다.** `main.ts:431` 의
   `onOpenModules: (resume) => modulesScreen.show(profile, () => resume())` 와 사령부의
   `suspend()`/`resume()` 쌍. `show()` 로 되돌리면 미저장 배치 편집이 날아간다.
   하네스 직행 `openModules`(`main.ts:2384`, `() => openBaseMap()`)도 그대로 둔다.
2. **조회 실패를 "비어 있음"으로 말하지 않는다.** `inventoryPanelKind`/`slotPanelKind`/

## 6-bis. 실화면 1차에서 잡은 것 넷 (2026-08-03)

계약대로 세운 뒤 하네스 실화면을 찍어 보니 **좌표 테스트가 전부 초록인 채로** 네 가지가 걸렸다.
전부 "값은 맞는데 화면이 틀린" 유형이라 여기에 남긴다.

1. **빈 자리가 패널이 아니라 행 안에 생겼다.** `fillRowHeights` 가 슬롯 2칸을 상한(240)까지
   늘리는데 빈 슬롯은 글자가 세 줄뿐이라 늘어난 판 **아래 150px** 가 통째로 빈 면이 됐다.
   상점 행도 같았다. → 내용을 `inner` 에 담아 최종 높이 안에서 **세로 중앙**에 놓는다.
   버튼도 판 바닥 고정을 그만두고 글자 뭉치 바로 아래로 흐르게 했다.
2. **같은 문장을 두 번 말했다.** 오프라인이면 슬롯·보관함이 똑같이 "서버 연결이 필요합니다"를
   띄웠다(상점에 대해서는 미리 막아 뒀던 함정에 정작 슬롯↔보관함에서 걸렸다).
   → 보관함은 `mod.inv.offlineNote`("보관함은 서버가 갖고 있습니다")로 갈랐다.
   같은 이유로 **조회 실패 시 `[다시 시도]` 는 하나만** 둔다 — 재조회 한 번이 둘을 같이 받아
   오므로 버튼이 둘이면 같은 일을 하는 버튼이 두 개다.
3. **비활성 금 버튼의 라벨이 사라졌다.** `PixiButton.setEnabled(false)` 는 container 알파를
   0.4 로 떨어뜨리는데, 금 톤은 라벨이 `COLOR.darkLabel`(진한 갈색)이라 밝은 판이 흐려지는
   순간 글자가 통째로 안 보인다 — `합성 확정 (2/3)` 과 `구매함` 이 **빈 판때기**로 찍혔다.
   정작 그 숫자가 사용자가 알아야 할 정보다. 옛 나무 구현도 같은 이유로 비활성이면 텍스처를
   `ui_btn_wood` 로 바꿨는데 전환하며 그 규율을 떨어뜨렸다. → `toneFor(tone, enabled)` 로
   비활성이면 석재 톤(라벨이 밝다)을 쓴다. **공용 `button.ts` 는 건드리지 않았다**(형제 화면
   여섯이 쓴다 — 같은 성질이 그 화면들에도 있을 수 있으나 이 레인의 범위가 아니다).
4. **하단 띠 왼쪽 아래가 비었다.** 토스트가 없으면 게이지만 위쪽에 붙어 아래 절반이 빈 자리가
   됐다. → 아래 줄이 비면 게이지가 **띠 세로 중앙**으로 내려온다.
