## 1. 이 화면 고유의 판단 여섯

### ① 창을 뚫는가 → **뚫지 않는다.** 정찰은 **감추는 것이 계약**인 화면이다

형제 화면 일곱의 결론: 창은 "배경이 보이는 구멍"이 아니라 **무언가를 보여주는 자리**다.
촉매 보관함·예비역 로스터·연구소·정제소는 초점 피사체가 없어 뚫었다 뺐고, 챔피언 선택(전용
함선 원화)과 방어 사령부(`createWorld` 실제 정지 렌더)만 뚫었다.

관제탑에서 "행을 바꾸면 바뀌는 피사체" 후보는 **기지 정찰**뿐이다. 그런데 정찰은 설계상
**정확 스펙을 내지 않는 것이 계약**이다(`src/ui/controlTower.ts` `reconView` — 실루엣 칩 ·
등급 색 · 승급 별만, 종류 이름은 1회 침공한 상대만 열린다). 여기에 방어 사령부식 실제 정지
렌더를 세우면 **감추기로 한 정보를 그림으로 통째로 흘린다** — 미관을 위해 기능 계약을 깨는
것이므로 금지다. 남는 후보는 "확대된 UI 칩"뿐이고 칩 조건은 창을 뚫지 않는다.

→ 패널 전부 `variant: 'slab'`. 배경 `windows: []`.

### ② **열을 고정한다** — 상태에 따라 열이 비는 것이 이 화면의 최대 위험이었다

옛 구현은 복수 대상 유무로 **2열/3열이 갈렸고**(`COLS_2` / `COLS_3`), 결과판 유무로 상단
상태 패널이 통째로 나타났다 사라졌다(`STATUS_MIN_H`/`STATUS_MAX_H`, 보드가 위로 올라옴).
즉 **같은 화면이 상태에 따라 네 가지 기하**를 가졌다. 재렌더 규율상 그때마다 배경과 석재
패널을 다시 구워야 하고, 화면 전환에서 판이 통째로 튄다.

→ **3열 고정.** 어떤 상태에서도 패널 셋의 사각형이 같다.

| 열 | 폭 | 내용 |
| --- | --- | --- |
| 침공 대상 | 640 | 대상 목록(일반/배치전 공통) |
| 기지 정찰 | 700 | 선택 대상 레이어 슬라이스 5장 |
| 작전 상황 | 460 | 내 전황 · 결과판 · 검증 중 · 배치전 · 복수 |

옛 "상단 상태 패널"(가로 전폭)과 옛 "복수 열"은 **작전 상황 한 열로 합친다** — 둘 다
조건부였고 둘 다 세로로 짧다. 합치면 조건부 기하가 사라진다.

⚠️ **대상 패널 제목은 배치전/일반에서 갈리지 않는다.** 각인 제목은 패널 텍스처에 구워지므로
제목이 상태에 따라 바뀌면 로드 완료 시 패널을 다시 구워야 한다. 제목은 `ctl.tgt.head`
하나이고, 배치전이라는 사실은 **작전 상황 열의 배치전 블록**이 이미 말한다(방어 사령부가
`배치 슬롯` 제목 하나로 세 레이어를 덮은 것과 같은 처방).

### ③ 빈 자리를 남기지 않는다 — 이 화면은 **비어 있는 상태가 정상**이다

오프라인·미로그인이면 목록 셋이 전부 null 이다. 그것이 "쉬고 있는 상태"이지 결함이 아니므로
**그 상태에도 처방이 적용돼야 한다**(칩 지시).

- 목록이 **짧으면** `fillRowHeights` 로 남는 세로를 행이 나눠 갖고, 상한 때문에 그래도 남으면
  그 자리를 **파낸 챔버**(`tailWell`)로 그린다.
- 목록이 **비었으면/오프라인이면** 패널 상자 전체를 **파낸 챔버**(`emptyWell`)로 그리고 그
  안에서 안내한다 — "빈 패널 면"이 아니라 "비어 있는 보관 챔버"가 된다.
- 정찰은 선택 전에도 챔버로 그린다.
- **작전 상황 열은 원리적으로 비지 않는다** — 맨 위 **내 전황 블록**(순위·전적·승률)이 상시
  들어가기 때문이다. 그래서 `fetchMyLadderRank()` 를 진입 로드로 끌어올린다(단건 RPC라
  가볍다. 200행 순위표 전체는 팝업이 열릴 때 그대로 늦게 받는다 — 진입을 무겁게 하지 않는다는
  기존 원칙 유지).

### ④ 하단 [기지로 돌아가기]는 **없앤다**

헤더 ✕ 와 같은 일(`back()`)을 두 번 제공하고 있었다 — 실제로 같은 함수를 부른다. 형제 화면
일곱은 전부 헤더 ✕ 하나만 쓴다. 하단 띠에는 **순위표 · 전투 기록 · 침공 알림**만 남고,
왼쪽 절반은 상태 문구가 쓴다(로딩/오프라인, 없으면 `ctl.sub`) — 띠 안에 빈 자리가 없다.

**침공 알림 버튼은 헤더에서 하단 띠로 내리고 상시 표시한다.** 옛 구현은 "내용이 있을 때만"
우상단에 띄웠는데, 그러면 헤더 우측이 상태에 따라 나타났다 사라진다(②와 같은 병). 미확인이
있으면 `gold`, 없으면 `stone` 이다 — 톤이 바뀌므로 **미확인 수가 바뀔 때만** 버튼을 다시
세운다(방어 사령부 `footBuiltDirty` 패턴).

### ⑤ 헤더에 **재화 칩을 두지 않는다**

이 화면은 크레딧·광물을 쓰지 않는다. 형제 화면의 칩 x(1424/1628)는 **재화를 쓰는 화면**의
어휘이고, 안 쓰는 화면에 칩을 얹는 것은 "그 화면의 결정을 돕지 않는 진입점"이다(§0-bis).
헤더는 각인 제목(중앙) + 닫기 ✕(x 1832) 둘뿐이고 나머지는 배경이 그대로 보이는 띠다.
옛 부제(`ctl.sub`)는 헤더에서 내려 **하단 띠 왼쪽의 쉬는 문구**로 재사용한다.

### ⑥ 팝업 넷은 **높이를 내용에서 역산**한다

`makeModal`(나무)은 고치지 않는다(다른 화면 다섯이 쓴다). 화면 파일 안에 시네마틱 팝업을
만들고 `modal.ts` 헤더 실측 규칙 3종을 승계한다: ①암막 불투명 ②암막이 이벤트를 먹음
③패널 안쪽 탭은 전파 차단.

⚠️ 알림 행은 옛 구현에서 **높이가 가변**이었다(문구 줄 수에 따라). 가변이면 높이를 역산할 수
없으므로 **행 높이를 고정**하고 문구를 그 안에서 접는다.

왼쪽 1084px 에는 상태 문구가 앉는다. 띠 안에 빈 자리가 없다.

### 팝업 — 높이를 **내용에서 역산**한다

| 팝업 | 폭 | 높이 역산식 | 클램프 |
| --- | --- | --- | --- |
| 순위표 | 1360 | `68 + 56+12 + 40 + n·44 + 12+52 + 24` | n = 11 고정 |
| 전투 기록 | 1360 | `68 + 46+12+24+8 + 40 + n·48 + 12+52 + 24` | n = 10 고정 |
| 침공 알림 | 1100 | `68 + (n·118 − 10) + 24` | n ∈ [2, 6] |
| 출격 기체 | 1000 | `68 + (n·100 − 12) + 24` | n ∈ [1, 6] |

`68 = TITLE_BAND_H(52) + CONTENT_GAP(16)`, `24 = EDGE_PAD`. 넷 다 **버려지는 세로가 0** 이고
단위 테스트가 등호로 잠근다.
암막 알파는 **0.97** 에서 시작하되 **실화면으로 확인**한다(예비역 0.92 · 챔피언 0.96 ·
연구소 0.98 · 방어 사령부 0.99 — 뒤 화면 밝기에 따라 다르다. 여기는 밝은 슬래브 셋이 화면을
거의 덮는다).

출격 `gold` · 페이지 이동 `stone` · 기록 필터 선택 `gold` / 미선택 `stone`.

형제 화면의 값(`SLAB_BODY_FILL 0xe4dac7` · `ROW_FACE 0x3b3327` · `ROW_GROOVE 0x17130d` ·
`rowPlate`/`rowRamp`/`recessedWell` · 여백 어휘 · 헤더 104 · `HEAD_Y 26`/`HEAD_H 52` ·
패널 상자 복제 상수 `EDGE_PAD 24`/`TITLE_BAND_H 52`/`CONTENT_GAP 16` · 닫기 x 1832)은
**복제하고 헤더에 출처를 밝힌다** — 그 파일들은 공용 모듈이 아니라 화면이다.

## 4. 재렌더 규율

현재 구현은 `render()` 가 루트를 통째로 지우고 다시 그린다. 그대로 두면 행 선택 한 번,
검색 한 글자마다 **배경과 석재 패널 셋이 다시 구워진다**.

- `buildChrome()` — 배경 · 패널 3장 · 헤더 · 하단 띠 그릇은 **한 번만**. 자산 도착 시 1회 재건.
  ⚠️ **크롬(헤더·하단 띠)은 패널보다 뒤에 붙인다**(§5-1).
- `syncValues()` — 하단 상태 문구 · 알림 버튼 톤(미확인 수가 바뀔 때만 재조립).
- `renderTargets()` / `renderRecon()` / `renderOps()` — 각자 host 안에서만.
- `renderModal()` — 팝업 host 안에서만.
- `update(dt)`: **`main.ts` 가 매 프레임 부른다**(`controlTower.update(frame)` 를
  `defenseCommand.update(frame)` 바로 옆에 배선). 숨겨져 있으면 즉시 반환.
  ⚠️ 연구소가 이 배선을 빠뜨려 배경·패널 연출이 통째로 멈춘 적이 있다.

## 5. 기능 불변식 — 깨면 즉시 불합격

1. ⚠️ **크롬은 패널보다 뒤에 붙인다.** Pixi v8 은 자식을 역순으로 훑다가 픽셀에 걸리면 거기서
   멈추고 가장 가까운 상호작용 조상을 반환한다 — 그림자 스프라이트가 `passive` 여도 탐색은
   끝난다. 석재 패널은 접지 그림자·글로우를 텍스처에 구워 **자기 사각보다 30px 가까이 번지므로**
   헤더·하단 버튼이 패널보다 먼저 붙으면 그 번짐에 클릭을 빼앗긴다(방어 사령부 실제 신고).
   여백으로는 못 푼다(번짐 폭이 패널 치수에서 파생돼 조용히 커진다). **소스 조립 순서를 테스트가
   잠근다.**
2. ⚠️ **흐림(미선택 0.72)은 `PixiButton` container 에 걸지 마라** — `pointerout` 이 alpha 를 1로
   되돌려 스쳐 지나가기만 해도 영영 풀린다. 감싸는 host 에 건다.
3. ⚠️ **`setEnabled(false)` + `gold` 톤 금지.** 컨테이너 alpha 0.4 + 어두운 갈색 라벨 + 그림자
   꺼짐이 겹쳐 **글자가 통째로 사라진다**. 비활성일 때는 크림 라벨인 `stone` 을 쓴다(톤이 바뀌므로
   상태가 **바뀔 때만** 버튼을 다시 세운다).
4. **`show()`/`hide()`/`visible` 공개 인터페이스와 콜백 타입을 바꾸지 않는다** — `main.ts` 가
   `ControlTowerCallbacks`/`ControlTowerShowOpts` 를 그대로 쓴다. **suspend/resume 은 없다.**
5. **`hide()` 는 `onInvade`·`pendingSortie`·`profile` 을 비운다.** `launchSortie`/`invade` 는
   `hide()` 전에 콜백과 대상을 **먼저 캡처**한다(기존 계약 — 순서를 바꾸면 침공이 조용히 죽는다).
6. **로드 race 토큰**(`loadToken`)을 유지한다. 낡은 응답이 새 화면을 덮어쓰면 안 된다.
7. **알림 확인 시각 갱신**(`writeInvasionsSeenAt`) 과 미확인 수 계산 순서를 바꾸지 않는다.
8. 배치전 판정(`placementPhase`)에 따라 대상 목록·쿨다운 규칙이 갈리는 분기
   (`computePlacementInvadeState` vs `computeInvadeState`)를 한 줄도 바꾸지 않는다.
9. **소집 팝업 취소(암막·닫기·Esc)는 출격을 취소한다** — `pendingSortie` 를 버린다.
10. ⚠️ 진입 시 런 HUD 숨김 · 닫을 때 **원래 값 복원**(`hudPrevVisibility`). 옛 구현은 무조건
    `visibility = ''` 로 되살렸다. `hudEl()` 에 캔버스 가드를 붙이지 않는다.
11. **휠 스크롤은 클립 Container 에**(마스크 Graphics 는 히트 테스트 제외). **행 클릭은 행
    Container 에**, 행 위 버튼은 `stopRowPropagation`.
12. **`SearchInput` 엘리먼트는 key 가 같으면 재사용한다** — 재생성하면 포커스와 한글 IME 조합이
    끊긴다. 팝업이 닫히면 `unmount`.
13. `Escape` 로 팝업을 닫는 `keydown` 리스너를 유지한다.
