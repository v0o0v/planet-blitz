## 1. 요구사항 요약

목표(마스터 §5): **엔드게임 대순환 완성 + CrazyGames 제출.** 범위:

1. **퇴역·수호 기체·계보** — 퇴역 플로우(수호 기체 생성·일괄 소멸 UI·새 기체 타입 해금 = **타이탄형/인터셉터형 스탯 프리셋 선택제**, §8 OQ-M5-3 확정), 수호 기체 AI(방어전 참전, 동시 2기), 수호 기체 풍화(주 5%p·바닥 50%)·소멸(전투력×성능 비례), 계보 트리(기체 가지+수호 가지, 로그 점근 +50%, 두 프리셋 공유).
2. **CrazyGames SDK** — 로그인 연동(Supabase 계정 링크), 리워드 광고 2지점(PvE 부활·정산 보너스), 진행도 클라우드 저장 병행, 포털 QA 가이드라인 점검.
3. **밸런싱 패스** — 티어 배율·드랍률·풍화 수치·계보 점근선 플레이테스트 튜닝.
4. **폴리시** — 사운드·격추 유머 다듬기·정산 화면 완성판·로컬라이즈(영어 우선, 한국어 병행).

6. **제출** — CrazyGames 개발자 포털 제출 → 피드백 반영 → 출시.

**비범위**: v1.1 로드맵(유성우·리플레이 극장 등 GDD §15), 세트·소켓·룬워드(출시 후 확장, GDD §5), 모바일(1차 데스크톱 전용, GDD §1).

## 2. 설계 원칙 + 핵심 결정 갈림길

### 설계 원칙
1. **결정론 승계(ADR-0005)**: 수호 기체는 방어전(침공 런)에 참전하는 **시뮬 엔티티** — 거동은 결정론(위치·타이머·스냅샷 스탯 함수). 방어전은 M4 침공 런과 동일 시뮬 코어, 수호 엔티티만 추가. 계보/퇴역/소멸/풍화 수치는 대부분 서버·메타(sim 밖)이나, 수호 성능%가 방어전 결과를 바꾸므로 **방어 배치 config에 수호 스냅샷+남은 성능% 포함**(서버 재현).
2. **무손실 철학 유지(ADR-0003·0007)**: 자동 소멸 없음(수호 바닥 50% 유지), 소멸은 유저 행동으로만. 계보 리스펙 없음(순환 재화). 퇴역 시 장비 원본 자동 창고 반환.
3. **스냅샷 정체(ADR-0007)**: 퇴역 순간 능력치 **복사 스냅샷** + 전투력 점수 기록. 좋은 장비로 퇴역할수록 강한 수호기·높은 회수가치.
4. **광고 없이도 무결(마스터 §6)**: 리워드 광고 2지점(PvE 부활·정산 보너스)은 개발 플래그로 M1~M4에서도 테스트 가능하게 설계. 미시청 시 게임 진행 무결.
5. **PvP 공정성 우선(GDD §1)**: 밸런싱 충돌 시 PvP 공정성 우선. 계보 무한 투자는 로그 점근(+50% 수렴)으로 고착화 방지(ADR-0007).

### 핵심 결정 갈림길

#### ① 수호 기체가 방어전에 반영되는 방식
| 옵션 | Pros | Cons |
|---|---|---|
| **A. 수호 = 방어 배치 config의 스냅샷 엔티티(스탯×남은 성능%×계보 보너스) ★채택** | M4 방어 배치 config·전수 재실행 재사용, 결정론 재현, 동시 2기 슬롯 자연 수용 | 수호 AI(추적형) 결정론 필요 |
| B. 수호를 서버가 실시간 별도 시뮬 | 유연 | 비동기 PvP·전수 검증 모델 붕괴, 비용↑ |
| C. 수호 효과를 방어 성공률 보정치로만 | 단순 | "이동형 요격 유닛"(GDD §4) 체감 상실, 검증 무의미 |

**채택 A 근거**: M4가 이미 방어 배치를 침공 런 config의 정적 스폰 데이터로 처리(M4 갈림길③A). 수호 기체를 **스냅샷 스탯 × 남은 성능% × 계보 수호 가지 보너스**로 산출한 엔티티로 방어 config에 넣으면, 방어전은 M4 침공 런에 수호 엔티티가 추가된 결정론 런이 되어 전수 재실행 그대로 성립. 수호 AI는 추적형 요격(GDD §4) — `nearestTarget`·이동 로직 결정론 재사용. B는 검증 모델 붕괴, C는 정체성·검증 상실로 기각.

#### ② 계보 점근형 수치 구조
| 옵션 | Pros | Cons |
|---|---|---|
| **A. 로그 스케일 점근(보너스 총합 +50% 수렴) ★채택 (ADR-0007)** | 무한 투자 허용 + PvP 고착화 방지, 운영자 선택 | 수렴 곡선 튜닝 필요 |
| B. 유한 트리(상한) | 명확한 천장 | 운영자 무한+로그 선택으로 기각(ADR-0007) |
| C. 선형 무제한 | 단순 | 고인물 무한 강화 → PvP 붕괴 |

**채택 A 근거**: ADR-0007 확정 — 무한 투자 가능하되 로그 스케일, 보너스 총합 +50% 수렴(📝 점근형). PvP 고착화 방지(GDD §1 공정성 우선). B는 ADR에서 기각됨, C는 PvP 붕괴로 기각.

#### ③ 리워드 광고 부재 시 게임 무결성
| 옵션 | Pros | Cons |
|---|---|---|
| **A. 광고 2지점을 개발 플래그로 추상화, 미시청 = 기본 진행 ★채택 (마스터 §6)** | 광고 SDK 없이 M1~M4 테스트 가능, 미시청 무결, 포털 QA 통과 | 광고 결과 훅 추상 계층 |
| B. 광고를 진행 필수 게이트로 | 수익↑ | 미시청 시 진행 불가 = 포털 QA·UX 실패 |
| C. 광고 로직을 코어에 직접 결합 | 단순 | 테스트·검증 어려움, SDK 의존 |

**채택 A 근거**: 마스터 §6·GDD §1 — 광고는 PvE 부활 1회·정산 보너스 2지점만, 침공 부활 불가. 광고 훅을 추상 인터페이스로 두고 미시청 시 기본 진행(부활 안 함·보너스 없음)이 무결하게. B는 QA/UX 실패, C는 테스트 곤란으로 기각.

> **≥2 viable option 확보**: 세 갈림길 모두 대안 2개 이상. 채택안의 기각 근거 명시.

## 3. 수용 기준 (AC)

- [ ] **AC6 (CrazyGames SDK)**: 로그인 연동(Supabase 계정 링크), 진행도 클라우드 저장 병행, 포털 QA 체크리스트(로딩·볼륨) 전 항목 통과(게이트③).

## 4. 구현 단계

> Phase A(수호/퇴역/계보)가 핵심 신규 시스템. B(광고)·C(폴리시)·D(성능/QA) 병행 가능, E 제출은 최후. **각 태스크 후 `npm test` + `tsc --noEmit`**.

### Phase A — 퇴역·수호 기체·계보 · 의존: M4
- **A1. 수호 기체 엔티티(방어전 AI)** — `src/sim/` 신규 kind + `data/`
  - `guardian` kind `KIND_CODE` append(M4 뒤 코드). 추적형 요격 유닛(GDD §4) — `nearestTarget`(`world.ts:684`)·이동 로직 결정론 재사용. 스탯 = 스냅샷 × 남은 성능% × 계보 보너스. 방어 배치 config에 수호 슬롯(동시 2기) 포함(M4 `defenses` 슬롯 자리 활성화).
- **A2. 퇴역 플로우** — `src/save/` + Edge Function + `src/ui/researchLab.ts`
  - 만렙 퇴역: 빌드·장비 스냅샷 → 수호 기체 생성(`guardians` 테이블), 전투력 점수 기록(장비·어픽스·빌드 종합). 장비 원본 자동 창고 반환(ADR-0007). **새 기체 타입 해금 = 선택제**(§8 OQ-M5-3 확정): 타이탄형(고HP·고화력·저속·대시 쿨다운↑) / 인터셉터형(고속·대시 특화·저내구) 중 스탯 프리셋 선택, 3계열 트리(화력/생존/기동)는 두 프리셋이 공유(전용 트리 분화는 출시 후 확장). 기존 수호 일괄 소멸 선택 UI.
- **A3. 수호 소멸·계보 회수** — Edge Function + `src/ui/defenseCommand.ts`
  - 소멸 = 전투력 점수 × 남은 성능% → 계보 포인트(상시 가능, 자동 소멸 없음, ADR-0007). 방어 사령부 UI.
- **A4. 수호 풍화** — pg_cron(M4 풍화 인프라 확장)
  - 수호 성능 주 5%p 감쇠·바닥 50%·회복 불가(ADR-0006 개정·0007). M4 정비도 풍화와 별도 대상. 하락 예고·알림.
- **A5. 계보 트리** — `data/lineage.ts` + `src/ui/researchLab.ts`
  - 기체 가지(내 기체 소폭 강화) + 수호 가지(모든 수호 강화). 로그 점근(+50% 수렴, 갈림길②A). 리스펙 없음. 포인트 원천: 퇴역 기본 지급 + 소멸 회수. 방어전 config가 수호 가지 보너스 소비(결정론 재현).

### Phase B — CrazyGames SDK · 의존: M4
- **B1. 광고 훅 추상화** — 신규 `src/platform/ads.ts`
  - PvE 부활 1회·정산 보너스 2지점. 추상 인터페이스 + 개발 플래그(마스터 §6). **미시청 = 기본 진행 무결**(부활 안 함·보너스 없음, 갈림길③A). 침공 부활 불가(GDD §8).
- **B2. SDK 연동·계정 링크** — 신규 `src/platform/crazygames.ts`
  - 로그인 연동(Supabase 계정 링크 — M4 익명 Auth → 링크), 진행도 클라우드 저장 병행(로컬+서버). 포털 QA 가이드라인(로딩 시간·볼륨) 점검.

### Phase C — 폴리시 · 의존: A
- **C1. 사운드·연출** — `src/render/` + `assets/`
  - 사운드(격추 유머 사출·낙하산 다듬기), 유니크 세리머니(M2)·보스 연출 폴리시.
- **C2. 정산 화면 완성판** — `src/ui/resultOverlay.ts`
  - 획득 장비·경험치·드랍·전투력 완성 UI, 광고 정산 보너스 지점.
- **C3. 로컬라이즈** — 신규 `src/i18n/`
  - 영어 우선(CrazyStorage 글로벌), 한국어 병행. UI 문자열 추출.

### Phase D — QA·성능 최종 · 의존: A,B,C
- **D1. 성능 벤치 재검증** — `src/bench/bench.ts`
  - 60fps/2,000발(무한 맵·기믹·수호 2기·5행성 포함). 오브젝트 풀·ParticleContainer 재점검.
- **D2. 크로스 브라우저** — Chrome·Edge·Firefox
  - 동작·성능·입력 검증. 장시간 세션 메모리 누수 점검(스냅샷·엔티티 풀).
- **D3. 밸런싱 패스** — `data/` 전반
  - 티어 배율·드랍률·풍화·계보 점근선 플레이테스트 튜닝(GDD §5 시작값 기준). PvP 공정성 우선.

### Phase E — 제출 · 의존: 전부
- **E1. 게이트 계측** — 퇴역 1사이클(①)·광고 미시청 무결(②)·포털 QA(③)
- **E2. CrazyGames 제출** — 개발자 포털 제출 → 피드백 반영 → 출시
- **E3. PR** — 분할 PR → 머지

## 7. 검증 단계

1. **결정론(수호 포함)**: `tests/` — 수호 2기 방어전 2회 해시 일치(AC2), M4 Deno parity에 수호 config 포함. CI 게이트 유지.
2. **퇴역 사이클 e2e**: 퇴역→수호→방어전→소멸→계보→다음 세대(AC1·게이트①).
3. **광고 무결**: 미시청 진행 무결(AC5·게이트②).
4. **SDK·포털**: 로그인·클라우드 저장·QA 체크리스트(AC6·게이트③).
5. **성능·크로스 브라우저**: 60fps/2,000발 + Chrome/Edge/Firefox + 메모리(AC9).
6. **타입/린트**: `tsc --noEmit` + ESLint — `src/sim/` 금지 심볼 0(AC10).
7. **회귀**: 전 마일스톤 테스트 통과.
