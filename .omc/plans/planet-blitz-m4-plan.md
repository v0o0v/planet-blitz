## 1. 요구사항 요약

목표(마스터 §4): **침공·래더·치트 방어 전체 가동.** 범위:

1. **Supabase 셋업** — project scope `.mcp.json`(전역 메모리 규칙 준수), 스키마 `profiles`·`ships`·`items`·`ladder`·`defenses`·`invasions`·`guardians`.
2. **시뮬 코어 Deno 포팅 검증** — Edge Function에서 시뮬 코어 실행 → 클라이언트와 해시 일치 e2e (**최우선 착수 — 실패 시 아키텍처 재논의 필요한 최대 리스크**).
3. **계정·세이브 이관** — Supabase Auth(익명 시작), 로컬 세이브 → 서버 이관 마이그레이션, PvE 런 결과 서버 기록.
4. **방어 배치 에디터** — 그리드 맵·**포탑 6종 확정**(①발칸 ②저격 ③산탄 ④감속 ⑤미사일 ⑥전격, §8 OQ-M4-1)·장애물·배치 포인트 예산제·코어, 방어 사령부 UI.
5. **침공 플로우** — 관제탑 상위 랭커 3명 제안(+30위 랜덤)·기지 정찰 뷰·침공 런(3분·부활 불가)·코어 파괴 판정.
6. **전수 검증** — 침공 리플레이 제출 → Edge Function 재실행 → 결과 확정·래더 스왑(Postgres 트랜잭션).
7. **래더** — 영구 순위표·스왑·**배치전**(NPC 시드 기지 5회→삽입)·비활성 침하(pg_cron)·복제 약탈.
8. **풍화·정비** — pg_cron 주간 정비도 -5%p, 정비 UI·예고 알림.
9. **NPC 시드 기지** — 난이도 분포 20개 설계·배치.
10. **PvE 샘플링 검증** — 상위 N%·통계 이상치·랜덤 재실행, 적발 시 런 무효+플래그.
11. **재미 요소** — 복수전(24h·쿨다운 무시)·도발 스티커(사전 세트 12종, 톤 확정: "가벼운 유머·도발, 조롱·모욕 아님" — 개별 목록은 착수 시 디자인 패스).
12. **리플레이 관전** — 침공당한 리플레이 재생 뷰.

**비범위**: 퇴역/수호 기체/계보(M5 — 단 방어 배치의 수호 기체 슬롯은 M5 훅 자리만), CrazyGames SDK(M5), 밸런싱 최종(M5).

## 2. 설계 원칙 + 핵심 결정 갈림길

### 설계 원칙
1. **결정론 = 무결성의 유일한 기반(ADR-0005)**: 침공은 서버가 [시드+입력+로드아웃+방어배치] 리플레이를 **전수 재실행**해 클라이언트가 보낸 결과(승패·해시)와 대조. 시뮬 코어는 클라이언트·Edge Function(Deno)에서 bit-identical. 이 규율이 뚫리면 영구 래더(ADR-0004)가 치터로 오염되고 복구 불가.
2. **서버 권위(server-authoritative)**: 순위 스왑·복제 약탈·풍화·침하는 Edge Function/pg_cron이 결정. 클라이언트 제출은 "증거(리플레이)"일 뿐 결과가 아님. Postgres 트랜잭션으로 원자적 스왑.
3. **무손실 철학(ADR-0003)**: 방어자는 패배해도 실물 손실 없음(복제 약탈). 풍화는 방어력(정비도·수호 성능)만 감쇠, 자원·장비·레벨·순위는 대상 아님(ADR-0006).
4. **계정 종속 MCP 격리(전역 메모리 규칙)**: Supabase MCP는 **project scope `.mcp.json`**(`project_ref` 고정), user scope 금지. 작업 전 `get_project_url`/`list_tables`로 대상 프로젝트 확인.
5. **방어 시뮬도 결정론**: 방어 배치(포탑·장애물·수호 슬롯)는 침공 런의 입력. 침공은 PvE와 동일 시뮬 코어에 방어 엔티티를 더한 결정론 런.

### 핵심 결정 갈림길

#### ① 시뮬 코어 Deno 재실행 방식 (최대 리스크)
| 옵션 | Pros | Cons |
|---|---|---|
| **A. `src/sim/` 순수 TS를 Edge Function에서 그대로 import(공유 소스) ★채택** | 단일 소스 = 로직 드리프트 0, lint가 이미 플랫폼 독립 보장, 해시 일치 자명 | Deno 번들·import 경로 정합 필요 |
| B. 시뮬 코어를 별도 재구현/포팅 | 런타임 최적화 여지 | 두 구현 드리프트 = 검증 붕괴(치명), 유지 2배 |
| C. WASM 컴파일 후 양쪽 로드 | 완전 동일 바이너리 | 빌드 파이프라인 복잡, f64 결정론은 이미 TS로 확보돼 이득 적음 |

**채택 A 근거**: ADR-0005·마스터 §6 — M1 lint가 `src/sim/`의 `Math.random`/`Date.now`/플랫폼 trig를 금지해 이미 플랫폼 독립. 같은 V8 계열(브라우저·Deno)이라 f64 연산 동일, `hashFloat`(`replay.ts:44-52`)가 raw IEEE-754 비트 비교. **동일 소스를 Edge Function이 import**하면 드리프트가 원천 차단된다. B는 드리프트로 검증 자체를 무력화(치명)하므로 기각, C는 이득 대비 복잡도 과다로 기각. **이 검증을 M4 최우선 착수**(Phase A)로 두어 실패 시 조기에 아키텍처 재논의.

#### ② PvE 검증 범위 (전수 vs 샘플링)
| 옵션 | Pros | Cons |
|---|---|---|
| **A. 침공=전수 재실행 / PvE=샘플링(상위 N%·이상치·랜덤) ★채택 (ADR-0005 확정)** | 침공 무결성 100% + PvE 컴퓨팅 비용 선형 회피 | PvE는 확률적 적발(정교 치트 일부 지연 적발) |
| B. 전 PvE 전수 검증 | 완벽 | Supabase 컴퓨팅 DAU 선형 → 비용 폭발(ADR-0005 기각됨) |
| C. 개연성 통계 상한만 | 저비용 | 슬로우핵·자동회피 봇 못 막음(ADR-0005 기각됨) |

**채택 A 근거**: ADR-0005 결정 승계. 침공은 래더 직결이라 전수, PvE는 샘플링 + 통계 이상치(시간당 획득 상한) + 적발 시 런 무효·계정 플래그(GDD §11). B·C는 ADR에서 이미 기각.

#### ③ 방어 배치의 리플레이 입력화
| 옵션 | Pros | Cons |
|---|---|---|
| **A. 방어 배치 = 침공 런 config의 일부(정적 엔티티 스폰 데이터) ★채택** | 침공이 순수 [시드+입력+config] 재현, 방어는 비동기 자동(스크립트) | 방어 AI(수호·포탑)도 결정론 필요 |
| B. 방어를 실시간 서버 시뮬로 별도 실행 | 유연 | 비동기 PvP(GDD §8)와 불합치, 비용·복잡도↑ |
| C. 방어 결과를 클라이언트가 계산 제출 | 단순 | 위조 가능 — ADR-0005 위배 |

**채택 A 근거**: GDD §8 — 방어는 비동기 자동. 방어 배치(포탑 6종·장애물·코어·수호 슬롯)를 침공 런 config의 정적 스폰 데이터로 넣으면, 침공은 PvE와 동일 시뮬 코어에 방어 엔티티를 더한 결정론 런이 되어 전수 재실행이 성립. 포탑·수호 AI는 결정론 거동(위치·타이머 함수). C는 위조 가능으로 기각, B는 비동기 모델 위배로 기각.

> **≥2 viable option 확보**: 세 갈림길 모두 대안 2개 이상. 채택안의 기각 근거 명시.

## 4. 구현 단계

> **Phase A(Deno 검증)를 절대 최우선**으로 완주한 뒤 나머지 착수. B~D는 A 통과 후 병행, E~G 순차. **각 태스크 후 `npm test` + `tsc --noEmit`**. Supabase 쓰기 작업은 대상 프로젝트 확인 후.

### Phase A — 시뮬 코어 Deno 재실행 검증 (최우선·게이트) · 의존: M3
- **A1. Edge Function 스캐폴드** — 신규 `supabase/functions/verify-run/`
  - `src/sim/` 공유 소스를 Deno import(갈림길①A). `runReplay`(`replay.ts:203`) 재사용. import 경로·번들 정합.
- **A2. 해시 일치 e2e** — 신규 `tests/deno-parity.test.ts` + Deno 실행 하니스
  - 대표 리플레이(5행성·전 기믹·보스·600s)를 브라우저(vitest)와 Deno에서 실행, 틱별 해시 스트림 bit 대조(AC1). **불일치 시 즉시 리드 보고·M4 중단**.
- **A3. 위조 공격 테스트** — `tests/`
  - 조작 해시·불일치 입력·트림 로그 제출 → 재실행이 100% 거부(AC2). 초월함수(있다면)·부동소수 경계 케이스 포함.
  - ⚠️ **A 통과가 M4 나머지의 전제**. 실패 시 마스터 리스크 톱1(검증 아키텍처 재설계) 발동.

### Phase B — Supabase 스키마·인프라 · 의존: A
- **B1. 프로젝트·MCP 격리** — `.mcp.json`(project scope)
  - Supabase 프로젝트 생성, `project_ref` 고정 `.mcp.json`(전역 메모리 규칙 — user scope 금지). 작업 전 `get_project_url` 확인.
- **B2. 스키마 마이그레이션** — `supabase/migrations/`
  - `profiles`·`ships`·`items`·`ladder`·`defenses`(배치 JSON+정비도)·`invasions`(리플레이·결과)·`guardians`(M5 대비 자리). RLS 정책(서버 권위 — 클라이언트 직접 순위 쓰기 금지).
- **B3. Auth·세이브 이관** — `src/save/` + Edge Function
  - 익명 Auth 시작, 로컬 `Profile`(M2 `src/save/profile.ts`) → 서버 이관 마이그레이션(`saveVersion` 활용). PvE 런 결과 서버 기록.

### Phase C — 방어 배치 + 침공 시뮬 · 의존: A
- **C1. 방어 엔티티(포탑 6종·장애물·코어)** — `src/sim/` 신규 kind + `data/`
  - **포탑 6종 확정**(§8 OQ-M4-1): ①발칸(단일 연사, 기본) ②저격(장거리 고피해 저속) ③산탄(근거리 부채꼴) ④감속(냉기장, 지원) ⑤미사일(제한 선회 유도) ⑥전격(연쇄 다수 약공). ④⑤⑥은 M3 산출물(상태이상·미사일 유형)을 재사용. 포탑·코어·장애물을 `EntityKind`/`KIND_CODE` append(M3까지 뒤 코드). 결정론 거동(포탑 = 자동 조준·발사, M2 `stepTurrets`(`world.ts:733`)·`nearestTarget` LOS 재사용). 코어 파괴 = 침공 승리 판정.
- **C2. 침공 런 모드** — `src/sim/world.ts` config 확장
  - 침공 config: 방어 배치(정적 스폰 데이터, 갈림길③A)·3분 제한·부활 불가. `createWorld`가 방어 엔티티 스폰. 승리 조건 = 코어 파괴(기존 `victory`), 실패 = 시간초과/격추(`gameOver`).
- **C3. 방어 배치 에디터 UI** — 신규 `src/ui/defenseCommand.ts`
  - 그리드 맵·포탑 6종·장애물·배치 포인트 예산제·코어 배치. 방어 사령부 진입(M3 기지 맵 "준비 중" → 활성화). 배치 JSON → `defenses` 저장. 수호 슬롯 자리(M5 비활성).

### Phase D — 침공 검증·래더 스왑 · 의존: A,B,C
- **D1. 전수 검증 Edge Function** — `supabase/functions/verify-invasion/`

  - 검증 통과 시 순위 스왑 + 복제 약탈(ADR-0003) 원자적 트랜잭션. 서버 권위(원칙2).
- **D3. 침공 플로우 UI** — 신규 `src/ui/controlTower.ts`

### Phase E — 래더 운영(배치전·침하·풍화) · 의존: B,D
