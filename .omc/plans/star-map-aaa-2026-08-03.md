## 0. 절대 규칙 (지시 수신소 §0 승계)

1. **순수 render/UI 레이어(ADR-0005)** — sim 을 읽지도 쓰지도 않는다. 시간축은 벽시계.
2. **품질 티어를 런타임 수렴 상태로 판단하지 마라**(`getActiveTier()` 단독 사용 금지).
3. **띠를 겹쳐 그라디언트를 근사하지 마라.** 램프는 폭 1px 캔버스에 픽셀로 굽고 `linear` 로 늘린다.
4. **Pixi v8**: `Sprite` 에 자식 금지(형제 + 변환 미러). `tint` 는 곱연산. 컬러 이모지 금지
   (`★ ✕ ▶ ◀ ≪ ≫ − +` 는 보존 목록).
5. 자산은 **덧붙임이지 전제가 아니다**. **이 레인은 새 자산을 만들지 않는다** — 창에 채우는
   것도 이미 리포에 있는 wang 타일셋이다(§1-①).
6. 캔버스 없는 환경(vitest)에서 `Text.width`·`document.createElement`·`ColorMatrixFilter`·
   `FillGradient` 가 전부 던진다. 관용구는
   `typeof document === 'undefined' || typeof document.createElement !== 'function'`.
   ⚠️ **캔버스 굽기 함수에만** 붙인다 — DOM 조회(`hudEl`)에 붙이면 HUD 숨김이 죽는다.
7. `npx tsc --noEmit` 0 · `npx eslint src tests --max-warnings 0`.

## 0-bis. 사용자가 **제거하기로 확정한 것** — 되살리지 마라

세로 석재 리브 · 가로 수평 이음선/코스 파편 · 각인 번호판 · 헤더 각인 석재 인방 ·
함선 도크 크래들. 남기는 것은 **재질과 조명뿐**. **면 위에 "부품"처럼 얹히는 표식은 넣지
않는다.** 그 화면의 결정을 돕지 않는 진입점도 넣지 않는다.

## 1. 이 화면 고유의 판단 다섯

### ① 창을 뚫는가 → **뚫는다.** 형제 화면들의 기각 사유가 여기서는 성립하지 않는다

기각의 근거는 언제나 **해상도**였다: 촉매 보관함·기록 보관소·지시 수신소는 후보 자산이
64×64 오브뿐이라 개구부를 채우면 17배 확대였다. 성계 지도의 후보는 다르다 — 실측:

| 후보 | 실측 | 판정 |
| --- | --- | --- |
| `assets/ui_planet_0..3.png` | 64×64, **행성 6종 중 4종만** | ✗ (형제들이 기각한 그것) |
| `textures.background[i]` | **절차 생성** 256×256 (단색 바탕 + 균열 3줄 + 잉걸 8점) | ✗ 화면에서 가장 정보가 없는 면(C1 재발) |
| `assets/tilesets/<planet>.png` | 128×256 아틀라스 = **32px wang 타일 16종**, **행성 6종 전부** | ✅ |

wang 타일셋은 **런에서 실제로 바닥에 깔리는 그 그림**이고(`AutotileBackground`, 32px 소스를
64px 로 그린다 — 게임 안과 **같은 배율**), 전 행성이 갖고 있으며, 개구부를 1:1 로 채운다.
"원본이 모자라 뭉갠다"도 "자산 없는 행을 고르면 창이 빈다"도 성립하지 않는다.
그리고 **행(행성)을 바꾸면 창이 바뀐다** — 창이 "배경이 보이는 구멍"이 아니라 **결정을 돕는
자리**여야 한다는 형제 화면 열의 조건을 그대로 만족한다. 여기가 곧 "이 행성이 어떻게 생겼나"다.

구현 규율:
- 내용물은 `box` 가 아니라 **`cinematicWindowOpening(...)`** 을 채운다(방어 사령부에서 `box` 에
  맞췄다가 위 16px·좌우·아래 17px 맨 배경 띠가 생겨 사용자가 신고했다).
- 내용물은 **창 패널 바로 뒤**에 둔다(앞에 두면 석재 단면·AO·유리 반사를 가려 개구부가 검은
  사각이 된다 — `defenseCommand.previewChildIndex` 와 같은 계약).
- 배경 `windows: [개구부의 화면 좌표]` — 창과 내용물이 어긋나면 밝기 보존이 헛돈다.
- 지형 시드는 **행성 id 파생**(결정론). 느린 세로 드리프트를 준다 — 런에서 바닥이 흐르는 방향.

### ② 카드 그리드인가 2열인가 → **2열(목록 / 상세) + 상세를 세로로 둘로**

옛 구현은 460×404 짜리 카드 6장을 가로로 늘어놓고(행 폭 1824) 그 아래 하단 패널 2장을
얹었다. 카드가 정보를 편 것이 아니라 **오브 하나 + 이름 + 부제 + 배율 한 줄**을 404px 높이에
띄엄띄엄 흘린 것이라, 카드 안 세로가 절반 이상 빈다(이 파일에 `CARD_SUB_MAX_BOTTOM` ·
`CARD_MULT_LINE_H` 같은 "겹치지 않게 띄우는" 상수가 쌓여 있는 것 자체가 증상이다).

2열이면:
- 목록 행이 **얇은 고정 높이**가 되고(오브 56 + 이름 + 부제 + 배율), 6장이 세로를 나눠 갖는다.
- 오른쪽이 **행을 바꿀 때마다 바뀌는 자리**가 된다 — 위는 그 행성의 전장(창), 아래는 출격 제원.
- 격납고 선례("밀도 높은 화면은 카드가 아니라 창을 뚫어라")와 정확히 같은 처방이다.

### ③ 재화 칩을 두지 않는다

촉매 주입은 **촉매 아이템**을 소모한다(`consume_catalysts`) — 크레딧·광물이 아니다. 출격도
무료다. 다만 `show({meta})` 가 넘기는 상태 줄(크레딧·광물·기체 Lv·스킬)은 **계약이라 반드시
표시한다** — 하단 액션 띠 왼쪽 첫 줄이 받는다. 형제 화면의 칩 x(1424/1628)는 재화를 **쓰는**
화면의 어휘이므로 얹지 않는다.

### ④ 촉매 픽커는 자리만 새로 잡는다

`CatalystPicker`(ADR-0029)는 다른 화면도 쓸 수 있는 모듈이므로 **한 줄도 고치지 않는다.**
성계 지도는 출격 제원 패널 오른쪽 챔버에 요약 + `[주입 편집]` 만 두고 팝업은 그대로 부른다.
주입/해제 → `sel.catalysts` → `consume_catalysts` 왕복 계약도 그대로다.

### ⑤ 빈 자리를 남기지 않는다

- 목록: 행이 `fillRowHeights` 로 남는 세로를 나눠 갖고, 그래도 상한에 걸려 남으면 **꼬리
  챔버**(`listFill`)가 받는다. 행성 6종이면 잔여 < 행 수라 꼬리는 안 생긴다(테스트가 등호로 잠근다).
  ⚠️ **`fillRowHeights` 는 늘려만 주고 줄여 주지 않는다** — `Math.max(h, Math.min(maxH, h+add))`.
  ⚠️ 목록 마스크에 **`clampToRows` 를 쓰지 않는다**(지시 수신소 §6-bis-4).
- 출격 제원: 챔버 둘(침략 단계 · 촉매 주입)이 상자 폭을 **등호로** 나눠 갖고, 각 챔버 안
  콘텐츠는 세로 중앙 정렬이 아니라 **위에서부터 채워** 아래 여백이 한 칸(≈14px)만 남는다.

## 2. 레이아웃 (디자인 스페이스 1920×1080)

여백 어휘(32 / 28 / 20 / 하단 28)와 헤더 높이 104 는 형제 화면과 **같은 값**이다.

| 요소 | x | y | w | h |
| --- | --- | --- | --- | --- |
| 헤더 밴드(배경 노출) | 0 | 0 | 1920 | 104 |
| 목록 패널(slab) | 32 | 124 | 520 | 848 |
| 전장 패널(**window**) | 580 | 124 | 1308 | 600 |
| 출격 제원 패널(slab) | 580 | 744 | 1308 | 228 |
| 하단 액션 띠 | 32 | 988 | 1856 | 64 |
| [장비 정비] | 1292 | 988 | 220 | 64 |
| [출격 {행성}] | 1528 | 988 | 360 | 64 |

전부 파생이다 — `PANEL_Y = GEAR_BAND_H + 4` · `FOOT_Y = 1080 − 28 − 64` ·
`PANEL_H = FOOT_Y − 16 − PANEL_Y` · `RIGHT_W = 1920 − 32 − RIGHT_X` ·
`OPS_H = PANEL_H − ARENA_H − 20`.
검산: `580 + 1308 = 1888 = 1920 − 32` ✓ · `744 + 228 = 972 = 124 + 848` ✓

헤더 컨트롤(y 26 · h 52): 닫기 ✕ x 1832 w 56 (= `onBack`, 기지 복귀). 좌측은 **비워 둔다**
(톱니 예약 밴드). 제목 대역은 중앙 ±280(`TITLE_BAND_HALF_W`).

### 패널 안 (제목 띠 있는 슬래브: box = x24 · y68 · w W−48 · h H−92)

- 목록 box = 472×756. 행 자연 높이 96(상한 130) · 간격 10 → 6장이면 117 씩, 잔여 4.
- 출격 제원 box = 1260×136. 챔버 둘: 침략 단계 **880** + 간격 24 + 촉매 **356** = 1260 ✓.
- 침략 단계 챔버(880×136): 1줄 = 머리글(좌) + `단계 N · 개방 상한 M`(우), 2줄 = 조절 행.
  조절 행 폭 836 ≤ 챔버 안 폭 848 ✓ (버튼 폭을 88/112/88/176/88/112/88, 간격 14 로 좁혔다).
- 촉매 챔버(356×136): 머리글 · 요약 2줄 · `[주입 편집]` 324×52.
- 전장 창 개구부 = `cinematicWindowOpening(1308, 600, true)` = x7 · y52 · 1294×541.
  64px 타일 21×9 = 189 스프라이트(런과 같은 배율, 확대 없음).

## 4. 재렌더 규율

현재 구현은 `render()` 가 루트를 통째로 지우고 다시 그린다(wipe-then-rebuild). 카드 한 번,
단계 한 칸마다 배경과 패널이 다시 **구워진다**.

- `buildChrome()` — 배경 · 패널 3장 · 헤더 · 하단 띠는 **한 번만**. 자산 도착 시 1회 재건.
  ⚠️ **크롬(헤더·하단 띠)은 패널보다 뒤에 붙인다**(§5-1).
- `renderList()` / `renderOps()` / `syncValues()` — 각자 host 안에서만.
- `syncArena()` — 행성이 **바뀔 때만** 타일셋 교체(같은 행성이면 no-op).
- `update(dt)`: **`main.ts` 가 매 프레임 부른다**(`planetSelect.update(frame)` 를
  `commissionDesk.update(frame)` 옆에 배선). 숨겨져 있으면 즉시 반환.

## 5. 기능 불변식 — 깨면 즉시 불합격

1. ⚠️ **크롬은 패널보다 뒤에 붙인다.** 석재 패널은 접지 그림자를 텍스처에 구워 자기 사각보다
   30px 가까이 번지고, Pixi v8 은 픽셀에 걸리면 거기서 멈춘다. **소스 조립 순서를 테스트가 잠근다.**
2. ⚠️ **`show()` 계약을 한 줄도 바꾸지 않는다** — `meta` · `bestStageCleared` · `onLaunch` ·
   `onInventory` · `onBack` · `fetchCatalystInventory`. `LaunchSelection` 은 DOM 판과 공유 타입이다.
3. ⚠️ **출격 계약**: `launch()` 는 `hide()` **먼저**, 콜백은 **먼저 캡처**, `sel` 은
   `{planet, stage, ...(cats.length>0 ? {catalysts} : {})}` 그대로. 여기서 config 를 손대지 않는다.
4. ⚠️ **`hide()` 는 멱등**이어야 한다 — `main.ts` 가 8곳 하네스 goto 스위치를 포함해 여러
   경로에서 부른다(716·1016·2209~2238·2306·2320·2576).
5. **모든 단계 이동은 `clampStageTo` 한 지점을 지난다**(`setStage` 유일 관문).
6. **행성 전환 시 특산 촉매 정합 정리**(`pruneInjectedForPlanet`)를 유지한다.
7. 공개 훅 유지: `getSelectedStage` · `getInjectedCatalysts` · `setInjectedCatalysts` ·
   `setCatalystInventory` · `openCatalystPicker` · `visible` (하네스·테스트 접점).
8. ⚠️ 진입 시 런 HUD 숨김 · 닫을 때 **원래 값 복원**(`hudPrevVisibility`).
   `hudEl()` 에 캔버스 가드를 붙이지 않는다.
9. **휠 스크롤은 클립 Container 에**(마스크 Graphics 는 히트 테스트 제외). **행 클릭은 행
   Container 에**(바탕 Graphics 에 걸면 위 텍스트가 삼킨다).
10. 단계 조절 버튼 라벨(`≪ −5 − 값 + +5 ≫`)과 출격 라벨(`▶ {name} 출격`)을 유지한다 —
    `tests/planetSelectStage.test.ts` 의 배선 검증이 라벨로 버튼을 찾는다.

## 6. 완료 기준

- **하네스 실화면 스크린샷**으로 확인 후 **사용자에게 제시**(비평은 사용자 요청 시에만).
  **행성 여러 종 전환 · 단계 하한/상한 · 촉매 0개/가득 · 오프라인(조회 실패)** 을 찍는다.
  `npx vite --port <빈 포트> --strictPort` → `?harness=1` → `pb.graphics quality:high` →
  `__pb.harness.preset('maxed')` → `__pb.openStarMap()`.
  ⚠️ 포트 충돌 주의(5180/5189/5231/5247/5311/5401/5477/5533 은 다른 워크트리가 쓴다).
  ⚠️ `Page.captureScreenshot` 은 창이 뒤에 있으면 오래된 프레임을 준다 — `bringToFront` 후
  rAF 실측 fps ≥ 30 확인 뒤 찍는다.
- 레이아웃 불변식 단위 테스트(`tests/planetSelectAaaLayout.test.ts`): 패널 겹침 · 헤더 침범 ·
  화면 이탈 · 톱니 예약 밴드 · 제목 대역 · **빈 자리 금지**(폭·세로 등호) · **패널 상자 기하
