# 격납고 화면 AAA 시네마틱 전환 — 레인 계약 (2026-08-02)

타이틀·인트로·기지를 시네마틱 키아트로 올린 뒤(PR#236·#238·#240·#245) 같은 붓을 다음
화면으로 롤아웃한다. 격납고가 그 대상이다.

**시각 정체성 = 시네마틱 전환**(사용자 확정). 나무 nine-slice(`ui_panel.png`·`ui_btn_*.png`)는
격납고에서 **은퇴**한다. 붓: 페인터리 디지털 페인팅, 금빛 고대 석재, 청록·자홍 성운, 짙은
실루엣, 따뜻한 금색 램프광.

## 0. 절대 규칙 (기지 계약 §0 을 그대로 승계)

1. **순수 render/UI 레이어(ADR-0005)** — sim 을 읽지도 쓰지도 않는다. 시간축은 벽시계.
2. **자기 파일만 만진다.** 아래 소유권 표를 넘지 마라. `hangar.ts` 는 **리드 전용**이다.
3. **품질 티어를 런타임 수렴 상태로 판단하지 마라** — `graphicsTierController.getActiveTier()`
   단독 사용 금지.
4. **띠를 겹쳐 그라디언트를 근사하지 마라.** 1px 겹침이 알파를 두 배로 만들어 가로줄이 생긴다
   (실제 사용자 신고). 램프는 폭 1px 캔버스에 픽셀로 굽고 `linear` 로 늘린다.
   ⚠️ `titleScreen.ts` 의 광선 스윕(`slabs = 7`)에는 이 결함이 **아직 남아 있다** — 복사 금지.
5. **Pixi v8**: `Sprite` 에 자식 금지(형제 + 변환 미러). `tint` 는 곱연산이라 밝히려면 가산
   오버레이. 컬러 이모지 금지(`text.ts` `stripEmoji`, `▶ ◀` 는 보존).
6. 자산은 **덧붙임이지 전제가 아니다** — 텍스처가 `undefined` 여도 화면이 서야 한다.
7. 캔버스 없는 환경(vitest)에서 `Text.width`·`document`·`new ColorMatrixFilter()` 가 **던진다**.
   전부 `try/catch` 로 방어하라(기존 모듈들이 쓰는 관용구를 그대로).
8. `npx tsc --noEmit` 0 · `corepack pnpm lint --max-warnings 0` 이 레인 종료 조건.

## 0-bis. 격납고 고유 규칙 — **기능을 깨면 즉시 불합격**

이 화면은 장식이 아니라 **정비 도구**다. 다음은 협상 대상이 아니다.

1. **등급 색은 파밍 시각 언어다.** `RARITY_COLOR_NUM` / `SLOT_RARITY_COLOR_NUM` /
   `SLOT_RARE_GROOVE` 값을 바꾸지 마라. `theme.ts` 헤더에 ΔE 실측 근거가 있다
   (레어 #FFEE7A 는 슬롯 프레임 금색과의 흡수를 푼 값이다).
2. **아이콘 대비 링**(`iconContrastRingBands`)의 "밝은 링이 아니라 어두운 홈" 결론을 존중하라.
   시네마틱 슬롯 프레임도 밝은 링을 두르면 안 된다.
3. **정보 밀도가 이 화면의 목적이다.** 배경·연출이 슬롯 아이콘·수치 가독성을 낮추면 그 처방이
   틀린 것이다. 기지의 베일·리브 값을 그대로 옮기지 마라 — 여기 기준으로 다시 잡는다.
4. **기능 동작 불변**: 요구 레벨 게이트(ADR-0030) · 중복 유니크 거부 · 휠 스크롤(클립
   Container 에, 마스크 Graphics 에 걸면 영영 안 불린다) · 좌/우클릭 이동 · 일괄 분해의
   "보이는 것 = 대상" 규율 · 하위 화면 `suspend()`/`resume()`.
5. **헤더는 겹치면 안 되는 세로 띠 4줄**이라는 과거 결함 이력이 있다(`hangar.ts`
   `BOTTOM_PY` 위 주석). 새 레이아웃도 같은 규율로 짠다.

## 1. 레이아웃 재설계 (리드 확정 — 레인은 이 좌표를 전제로 만든다)

### 왜 재설계가 필요한가

기존 4패널은 화면의 **약 97%** 를 덮는다(좌우 여백 24 · 거터 20). 기지의 "배경 위에 뜬 카드"
언어가 여기서는 **성립할 수 없다** — 배경을 아무리 잘 그려도 보이는 자리가 없다.

그래서 배경을 **패널 뒤가 아니라 패널 안**으로 들여온다: 기체 쇼케이스 패널을 불투명 채움이
아니라 **배경이 비치는 도크 창**으로 만든다. 그 창(936×500 = 화면 22.6%)과 헤더 밴드
(1920×104 = 9.6%)를 합쳐 **약 32%** 가 실제 키아트다. 나머지는 석재 슬래브가 덮는다 —
그게 정직한 구성이다(AAA 허브는 배경을 넓게 보여주는 게 아니라 **창을 뚫는다**).

### 좌표 (디자인 스페이스 1920×1080)

| 요소 | x | y | w | h |
| --- | --- | --- | --- | --- |
| 헤더 밴드(배경 노출) | 0 | 0 | 1920 | 104 |
| 스탯 패널 | 32 | 112 | 892 | 496 |
| 쇼케이스 패널(**창**) | 952 | 112 | 936 | 496 |
| 창고 패널 | 32 | 628 | 892 | 424 |
| 인벤토리 패널 | 952 | 628 | 936 | 424 |

- 좌우 여백 **32**, 중앙 거터 **28**, 행 간격 **20**, 하단 여백 **28**.
- 패널 접지 그림자는 아래로 최대 48px 번지므로 행 간격 20 은 **부족하다** → Lane B 는
  하단 그림자를 패널 **바깥으로 그리되** 위 행의 그림자가 아래 행 패널 위에 얹히는 것은
  구조상 불가피하다. 리드가 z 순서로 위→아래 순 배치해 아래 행이 위 행 그림자를 덮게 한다.
- 힌트 줄은 y 1058(하단 패널 바닥 1052 아래).

## 3. 인터페이스 계약 (리드가 이 시그니처로 조립한다 — 바꾸지 마라)

### Lane A — 배경

```ts
// hangarTextures.ts
export const HANGAR_BACKDROP_NAME = 'hangar_backdrop.webp';
export const HANGAR_ASSET_NAMES: readonly string[];
export type HangarTextures = Partial<Record<string, Texture>>;
export function hangarAssetUrl(basename: string): string | undefined;
export function loadHangarTextures(): Promise<HangarTextures>;

// hangarBackdrop.ts
export interface HangarWindowRect { x: number; y: number; w: number; h: number }
export interface HangarBackdropOpts {
  /** 배경이 **그대로 보여야 하는** 창(쇼케이스 패널 자리). 여기만 밝기를 보존한다. */
  windows: readonly HangarWindowRect[];
  /** 헤더 밴드 높이 — 그 위쪽은 중간 세기로 누른다(제목·칩이 얹힌다). */
  headerH: number;
}
export class HangarBackdrop {
  constructor(tex: Texture | undefined, opts: HangarBackdropOpts);
  readonly view: Container;   // 리드가 root 맨 뒤에 붙인다
  update(dt: number): void;   // dt 는 벽시계 초
  destroy(): void;
}
```

Lane A 가 책임지는 것:

- 풀블리드 커버 + 오버스캔 · **아주 절제된** 마우스 패럴랙스(기지 `MOUSE_RANGE=11` 의 **절반
  이하**로 — 여기는 조작 화면이라 배경이 움직이면 클릭이 흔들리는 느낌을 준다) · 자동 드리프트.
- **창 안**: 밝기·채도를 보존하고 티끌·아주 느린 램프 맥동만. 창이 이 화면의 유일한 볼거리다.
- **창 밖**: 강하게 누른다(패널이 덮으므로 낭비를 줄이고, 패널 가장자리에서 새어 보이는 부분이
  패널보다 밝으면 도-지 반전이 난다 — 기지 2라운드에서 실제로 겪은 결함).
- 헤더 밴드: 중간 세기. 제목 새김과 재화 칩이 얹히므로 **글자 대비 4.5:1 이 성립할 만큼**은
  눌러야 하지만, 완전히 눌러 검게 만들면 헤더가 다시 평면이 된다.
- 하단 비네트 · 가장자리 비네트.

⚠️ **지표 규율**(기지에서 두 번 뒤로 간 원인): 배경 균일도를 **상한**으로 걸지 마라. 배경이
회화이기를 그만두게 만든다. 대리 지표는 **보존해야 할 것의 하한**으로만 쓴다.

### Lane B — 석재 패널

```ts
// cinematicPanel.ts
export interface CinematicPanelOpts {
  width: number; height: number;
  /** 'slab' = 불투명 석재(스탯·창고·인벤토리). 'window' = 배경이 비치는 유리창(쇼케이스). */
  variant: 'slab' | 'window';
  /** 각인 제목(없으면 헤더 띠를 그리지 않는다). */
  title?: string;
}
export interface CinematicPanelBox {
  x: number; y: number; w: number; h: number; right: number; bottom: number;
}
export interface CinematicPanel {
  readonly container: Container;
  /** 콘텐츠를 놓아도 되는 패널 로컬 상자. 헤더 띠가 있으면 그 아래부터다. */
  readonly box: CinematicPanelBox;
  /** 제목 띠 바로 아래 y(패널 로컬) — 리드가 액션 행을 여기부터 쌓는다. */
  readonly headerBottom: number;
  update(dt: number): void;
  destroy(): void;
}
export function makeCinematicPanel(o: CinematicPanelOpts): CinematicPanel;
```

Lane B 가 책임지는 것 — **나무 nine-slice 를 쓰지 않는** 석재 슬래브:

- 방향성 베벨(위/왼쪽 립 + 아래/오른쪽 그늘 + 립 안쪽 어두운 홈). 사방 균일 밝은 스트로크는
  **금지** — `cinematicTile.ts` `BEVEL_LIGHT` 헤더에 실측 근거가 있다(편차 4L 짜리 균일
  스트로크가 "오려 붙인 웹 카드"로 읽혔다).
- 2단 접지 그림자(좁고 짙은 접촉 + 넓고 옅은 확산). 한 층으로는 접지가 안 읽힌다.
- 미세 그레인(±3L). 완전히 평평한 면은 유화 옆에서 CSS `div` 로 읽힌다(실측 std 1.42 사례).
  ⚠️ 흰 점/검은 점 알파는 **비대칭**이어야 한다(합성이 비대칭이라 같은 값을 쓰면 얼룩이 쏠린다).
- 각인 제목 띠: 금박 각인 + 그 아래 얇은 홈. 제목 위·아래로 자기 띠를 통째로 갖는다.
- `variant: 'window'` — 내부 채움 없음(배경이 그대로 비침) + 안쪽 가장자리 AO + 유리 반사
  하이라이트 한 줄 + **바닥 쪽만** 옅은 스크림(그 위에 슬롯 라벨이 얹힌다).
- `variant: 'slab'` — 따뜻한 석재 세로 램프. **배경(눌린 상태)보다 밝아야** 물체로 선다.
  figure-ground 는 테두리가 아니라 **면의 밝기**가 만든다.

Lane C 가 책임지는 것: 전부 **절차적**(Graphics/Text/구운 캔버스). 새 자산을 요구하지 마라.
기존 컴포넌트(`PixiButton` · `makeSlotCell`)를 **수정하지 말고 텍스처만 주입**하는 것이 규율이다 —
그 컴포넌트들은 다른 화면 6곳이 쓰고 있다.

⚠️ 슬롯 텍스처는 `makeSlotCell` 이 `size` 정사각으로 늘려 쓴다(현재 62px·72px 두 가지).
구운 텍스처는 그 두 배 이상 해상도로 구워 `linear` 로 축소되게 하라 — 확대되면 흐려진다.

## 4. 완료 기준 (레인)

- `npx tsc --noEmit` 0 · `corepack pnpm lint` 0.
- 자기 모듈이 **텍스처 없이도** 예외 없이 컨테이너를 돌려준다(폴백 경로).
- 헤더 주석에 **왜 그렇게 했는지**를 남긴다(무엇이 아니라 왜). 서브에이전트 트랜스크립트는
  만료되므로, 후임이 이어받을 수 있는 유일한 기록이 그 헤더다.
- 리드에게 돌려줄 최종 텍스트: 만든 파일 목록 + 리드가 알아야 할 제약 3줄 이내.

## 5. 완료 기준 (레인 종료 후 리드)

- 하네스 실화면 스크린샷. 품질 티어 `high` 고정 · 탭 포그라운드 · 커서를 프레임 밖으로.
- **엄격한 비평 서브에이전트**가 실측으로 AAA 판정. 기본 입장은 불합격.
  ⚠️ 처방을 레인에 내리기 전에 **그 지표가 올바른 축을 재고 있는지 먼저 검토**한다.
- 자산 결손 가드(양방향 + 용량 예산) · `renderWiring` · 전체 vitest · `tsc` · `eslint`.
- 전체 스위트의 기존 적색(sim·밸런스·골든 계열)은 **수와 파일이 같은지** 대조해 회귀가
  아님을 증명한다.

## 6. 지표 운용 규율 (기지 7라운드에서 산 교훈 — 반드시 승계)

1. 대리 지표를 **"균일해야 할 것의 상한"** 으로 주면 그림이 지워진다. 하한(보존)으로만 안전.
2. **평균은 결함을 가린다.** 게이트는 `타일 최소` + `임계 미만 픽셀 비율`로.
3. **가정한 상수를 잰 픽셀로 착각**하면 지표가 참인 채로 틀린다 → 대비는 **곱연산(AO)** 으로.
4. **절대 델타는 곱연산 편차의 지표가 아니다**(`Δ = bg × (1−ratio)`).
5. **표본 정의가 다르면 반대 결론이 나온다** → 수 대신 **정의 비의존 속성**을 보고하게 하라.
6. **판정 기준은 스크린샷이고 수치는 대리 지표다.** 수치를 맞추다 화면이 나빠지면 수치를 버려라.
