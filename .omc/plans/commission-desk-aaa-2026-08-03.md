## 0. 절대 규칙 (기록 보관소 §0 승계)

1. **순수 render/UI 레이어(ADR-0005)** — sim 을 읽지도 쓰지도 않는다. 시간축은 벽시계.
2. **품질 티어를 런타임 수렴 상태로 판단하지 마라**(`getActiveTier()` 단독 사용 금지).
3. **띠를 겹쳐 그라디언트를 근사하지 마라.** 램프는 폭 1px 캔버스에 픽셀로 굽고 `linear` 로 늘린다.
4. **Pixi v8**: `Sprite` 에 자식 금지(형제 + 변환 미러). `tint` 는 곱연산. 컬러 이모지 금지
   (`★ ✕ ▶ ◀` 는 보존 목록).
5. 자산은 **덧붙임이지 전제가 아니다**. **이 레인은 새 자산을 만들지 않는다.**
6. 캔버스 없는 환경(vitest)에서 `Text.width`·`document.createElement`·`ColorMatrixFilter`·
   `FillGradient` 가 전부 던진다. 관용구는
   `typeof document === 'undefined' || typeof document.createElement !== 'function'`.
   ⚠️ **캔버스 굽기 함수에만** 붙인다 — DOM 조회(`hudEl`)에 붙이면 HUD 숨김이 죽는다.
7. `npx tsc --noEmit` 0 · `npx eslint src tests --max-warnings 0`.

## 1. 이 화면 고유의 판단 다섯

### ① 창을 뚫는가 → **뚫지 않는다.** 행성 자산은 64×64 오브뿐이다

형제 화면 열의 결론: 창은 "배경이 보이는 구멍"이 아니라 **무언가를 보여주는 자리**다.
여기서 유일한 후보는 **의뢰 대상 행성**(`payload.segments[].planet`)인데 실측하면

| 후보 자산 | 원본 해상도 |
| --- | --- |
| `assets/ui_planet_0..3.png` | **64×64** (행성 6종 중 4종만 존재) |
| `assets/boss_*.png` | 128×128 |
| `assets/hangar/hangar_backdrop.webp` · `assets/intro/*.webp` | 1376×768 (행성별이 아니다) |

상세 열의 개구부는 `cinematicWindowOpening(1108, 848, true)` ≈ 1094×774 라, 64px 오브를
채우면 **17배 확대**다(기록 보관소가 5.4배로 이미 기각했다). 게다가 행성 6종 중 둘은 자산이
아예 없어 "행을 바꾸면 창이 비는" 상태가 정상이 된다.

→ 패널 둘 다 `variant: 'slab'`. 배경 `windows: []`.

### ② 1열인가 2열인가 → **2열 목록/상세**

옛 구현은 1200×830 패널 하나에 **168px 짜리 두꺼운 행**을 쌓고 좌우 720px 을 통째로 비워
뒀다. 행 안에 계급·주문·보상 요약·제약 문구·[출격] 버튼이 전부 들어가 있었고, 제약 문구 줄
수가 의뢰마다 달라 **행 높이를 역산할 수 없는 구조**였다(기록 보관소의 가변 행 높이와 같은 병).

2열로 가면:
- 목록 행이 **얇아지고 고정 높이**가 된다(계급·주문 + 무대 수·크레딧 한 줄).
- 상세 열이 **행을 바꿀 때마다 바뀌는 자리**가 되어 오른쪽이 비지 않는다.
- 제약 문구의 가변 길이는 상세 열의 **챔버 + 스크롤**이 흡수한다.

### ③ 탭을 두지 않는다 — 목록이 하나뿐이다

기록 보관소는 탭이 둘(파일럿 파일 · 기록 파편)이었지만 여기는 보유 의뢰서 목록 하나다.
탭 줄을 만들면 칸이 하나뿐인 탭 줄이 되어 죽은 자리가 된다.
→ 패널이 **설정 톱니 예약 밴드 바로 아래**(`GEAR_BAND_H + 4 = 124`)에서 시작한다.
헤더 밴드(104)와의 20px 차는 톱니가 쓰는 자리다(빈 자리가 아니다).

### ④ 헤더에 **재화 칩을 두지 않는다**

이 화면은 크레딧·광물을 **쓰지 않는다** — 의뢰서는 보스 처치로 얻고 출격은 무료다. 옛 구현이
`makeCurrencyChip` 둘을 얹은 것은 형제 화면 복사의 잔재다. 형제 화면의 칩 x(1424/1628)는 재화를
쓰는 화면의 어휘이고, 안 쓰는 화면에 얹는 것은 "그 화면의 결정을 돕지 않는 진입점"이다(§0-bis).
헤더는 각인 제목(중앙) + 닫기 ✕(x 1832) 둘뿐이다.

### ⑤ 빈 자리를 남기지 않는다 — ⚠️ **기본 상태가 "보유 0 · 오프라인"이다**

의뢰서는 **서버 원장이 정본**이고 무의뢰 폴백이 없다 — 미로그인/오프라인이면 목록이 **항상**
비어 있다. 그러니 그 화면이 이 화면의 **기본 상태**이고, 처방은 거기에 먼저 적용돼야 한다
(관제탑 §1-③ 과 같은 판단).

- 목록이 비면 목록 상자 전체가 **파낸 챔버**(`emptyWell`)가 되고 그 안에서 안내한다
  (오프라인이면 `commission.offline`, 온라인인데 0장이면 `commission.empty`).
- 상세 열도 같은 처방(`commission.detail.empty`).
- 목록이 짧으면 `fillRowHeights` 로 행이 남는 세로를 나눠 갖는다(보유 1..12장 전 구간에서
  상한 전에 채워진다 — 테스트가 등호로 잠근다).
- ⚠️ **`fillRowHeights` 는 늘려만 주고 줄여 주지 않는다.** 상한 12장이면 자연 높이 합이
  상자를 넘으므로 **목록에 스크롤**을 붙인다. 상세 챔버도 제약 문구 줄 수가 가변이라 스크롤을
  붙인다. 산술은 `Math.max(h, Math.min(maxH, h + add))` 로 감싼다(안 감싸면 긴 행이 깎여
  내용이 판 밖으로 튄다 — `modulesView.ts` 에서 실제로 터졌다).

### ⑤-bis. 재고 문구·상태 문구·[출격] 은 **하단 액션 띠**가 받는다

옛 구현의 재고 문구는 패널 안 우상단, 오류 힌트는 화면 맨 아래 중앙에 떠 있었다. 둘 다 하단
띠로 내린다 — 띠 왼쪽에 **두 줄**(보유 N/12 · 상태 문구), 오른쪽에 `[출격 320]`.
상태 문구는 오류가 있으면 오류, 없으면 부제(`commission.sub`)다. 띠 안에 빈 자리가 없고
`commission.sub` 도 고아 키에서 벗어난다.

## 4. 재렌더 규율

현재 구현은 `render()` 가 루트를 통째로 지우고 다시 그린다(wipe-then-rebuild). 그대로 두면
행 클릭 한 번, 재고 갱신 한 번마다 **배경과 석재 패널이 다시 구워진다**.

- `buildChrome()` — 배경 · 패널 2장 · 헤더 · 하단 띠는 **한 번만**. 자산 도착 시 1회 재건.
  ⚠️ **크롬(헤더·하단 띠)은 패널보다 뒤에 붙인다**(§5-1).
- `syncValues()` — 재고 문구 · 상태 문구 · [출격] 버튼(상태가 바뀔 때만 재건).
- `renderList()` / `renderDetail()` — 각자 host 안에서만.
- `update(dt)`: **`main.ts` 가 매 프레임 부른다**(`commissionDesk.update(frame)` 를
  `recordsArchive.update(frame)` 바로 옆에 배선). 숨겨져 있으면 즉시 반환.

## 5. 기능 불변식 — 깨면 즉시 불합격

1. ⚠️ **크롬은 패널보다 뒤에 붙인다.** Pixi v8 은 자식을 역순으로 훑다가 픽셀에 걸리면 거기서
   멈추고 가장 가까운 상호작용 조상을 반환한다 — 그림자가 `passive` 여도 탐색은 끝난다.
   석재 패널은 접지 그림자를 텍스처에 구워 **자기 사각보다 30px 가까이 번진다.**
   여백으로는 못 푼다. **소스 조립 순서를 테스트가 잠근다.**
2. ⚠️ **출격 서버 왕복 재진입 가드(`busy`)와 self-hide → `onLaunch` 순서를 한 줄도 바꾸지
   않는다.** `hide()` 가 `cb` 를 비우므로 콜백은 **먼저 캡처**한다.
3. ⚠️ **`commissionSealedLoadout(profile, row.payload.constraints?.equipRules)`** 를
   `buildRunConfig` 와 **같은 함수·같은 인자**로 부른다 — 여기서 다르게 계산하면 정직한 런도
   `commission-loadout-mismatch` 로 거부된다.
4. **`show(profile, cb)` / `hide()` / `visible` 공개 인터페이스와 `CommissionDeskCallbacks`
   (`onClose` · `onLaunch`)를 바꾸지 않는다.** 생성자가 `profile` 을 받는 것(`new
   CommissionDeskScreen(profile, gameApp.stage)`)도 그대로다 — 형제 화면과 다르지만
   `main.ts:411` 이 그렇게 쓴다. **suspend/resume 은 없다**(show/onClose 규약).
5. **오프라인/미설정이면 출격을 막는다** — `fetchCommissionInventoryOnline()` 이 `null` 이면
   `online=false` 이고 목록이 비며 [출격] 이 비활성이다.
6. ⚠️ 진입 시 런 HUD 숨김 · 닫을 때 **원래 값 복원**(`hudPrevVisibility`).
   `hudEl()` 에 캔버스 가드를 붙이지 않는다.
7. **휠 스크롤은 클립 Container 에**(마스크 Graphics 는 히트 테스트 제외). **행 클릭은 행
   Container 에**(바탕 Graphics 에 걸면 위 텍스트가 삼킨다).
8. **`raise()`** — `show()` 에서 root 를 stage 최상위로 올리는 거동을 유지한다.
9. 표시 판정(라벨·보상 요약·제약 문구·재고 문구)은 계속 `commissionDeskView.ts`(순수 계층)가
   소유한다. 화면은 그 함수만 부른다.

## 6. 완료 기준

- **하네스 실화면 스크린샷**으로 확인 후 **사용자에게 제시**(비평은 사용자 요청 시에만).
  **보유 0/오프라인 · 목록이 찬 상태 · 출격 중(busy)** 셋을 찍는다.
  `npx vite --port <빈 포트> --strictPort` → `?harness=1` → `pb.graphics quality:high` →
  `__pb.harness.preset('maxed')` → `__pb.openCommissionDesk()`.
  ⚠️ 다른 워크트리가 5189/5231/5247/5311/5401/5477 을 쓰면 **엉뚱한 워크트리가 서빙된다**.
  ⚠️ `Page.captureScreenshot` 은 창이 뒤에 있으면 오래된 프레임을 준다 — `Page.bringToFront`
  후 rAF 실측 fps ≥ 30 을 확인하고 찍는다.
  ⚠️ 보유 목록은 서버 원장에서 온다 — 로그인 없이는 항상 비어 있다. `__pb.commissionDesk` 로
  `inventory`·`online` 을 직접 시딩해 **찬 화면**도 찍는다.
- 레이아웃 불변식 단위 테스트(`tests/commissionDeskAaaLayout.test.ts`): 패널 겹침 · 헤더 침범 ·
  화면 이탈 · 톱니 예약 밴드 · 제목 대역 · **빈 자리 금지**(2열 폭 등호 · 패널 세로 등호 ·
  하단 띠 등호) · **패널 상자 기하 복제본 드리프트** · **크롬/패널 조립 순서** · `main.ts`
  update 배선 · **봉인 로드아웃 호출 형태** + **뮤테이션으로 유효성 확인**.
  ⚠️ **살아 돌아온 뮤테이션을 그냥 넘기지 마라** — 파생값 단언은 항진이다.

## 6-bis. 구현이 계약을 고친 자리 (2026-08-03 실측 후 반영)

계약을 쓸 때는 몰랐고 **테스트와 실화면이 잡아서** 바뀐 넷. 전부 "형제 화면들은 목록 길이가
데이터로 고정인데 여기는 0..12 로 변한다"에서 나왔다.

1. **꼬리 챔버(`listFill`)** — 보유 1~5장이면 행이 상한(120)에 먼저 걸려 목록에 최대 626px 가
   통째로 빈다. **단위 테스트가 먼저 잡았다**(`1장에서 목록에 빈 면이 남는다: 636`). 남는 자리를
   파낸 챔버가 받고 "아직 자리가 남았다"를 말한다.
2. **상세 챔버는 왼쪽 라벨 + 오른쪽 값** — 머리글을 본문 위에 얹었더니 1060px 열의 오른쪽
   700px 가 비었다(실화면 1차). 지시서가 실제로 읽히는 형태이기도 하다.
3. **빈 상세 열은 안내 챔버 셋**(`renderPrimer`) — 한 줄 안내를 넣었더니 1060×756 빈 상자가
   이 화면의 **첫인상**이 됐다. 그 상태에서 알아야 할 것은 "고르라"가 아니라 "어떻게 얻고 몇
   장까지 쌓이는가"다. 채워진 화면과 **같은 챔버 기계**를 쓴다.
4. **목록 마스크에 `clampToRows` 를 쓰지 않는다** — 12장이면 행 경계로 잘려 상자 아래 78px 가
   맨 석재로 남았다. 상자 높이를 그대로 쓰면 마지막 행이 반쯤 걸쳐 "더 있다"를 말한다.

### 뮤테이션 결과 (18건 중 16 KILLED · 2 SURVIVED)

살아 돌아온 둘을 그냥 넘기지 않았다.

- `LIST_W 720 → 760` **SURVIVED — 옳다.** 그 값에서도 두 열이 다 담긴다. 폭 자체를 못 박으면
  값을 지키는 게 아니라 값을 **베끼는** 테스트가 된다. 극단(`1300`)은 `chamberTextW` 하한이
  잡는다(M5 KILLED). 주석으로 근거를 남겼다.
- `main.ts` 의 `commissionDesk.update(frame)` **주석 처리 SURVIVED — 결함이었다.**
  `toContain('commissionDesk.update(frame)')` 는 **주석 줄도 문자열을 품는다.**
  `/^[ \t]*commissionDesk\.update\(frame\);/m` 로 바꿔 KILLED 확인.
  ⚠️ **같은 항진이 형제 화면 테스트들에 그대로 있다**(`recordsArchive`·`controlTower` 등) —
  다음 레인에서 함께 고칠 자리다.
