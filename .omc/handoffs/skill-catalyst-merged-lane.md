### 2-4. ⚠️ `skillCarry` 는 **참조 대입 그대로다 — 값 복사로 바꾸지 마라**

`commissionCarry.test.ts` 의 CARRY 대조가 `toBe`(= `Object.is`, 배열이면 **참조 동일성**)라,
`slice()` 로 "안전하게" 복사하면 **오히려 빨개진다.** `weapon`·`loot` 와 같은 규율이고 근거는
"이전 월드는 전환 직후 버려진다"이다.

그 테스트가 **8칸 중 4칸만 이월하는 결함을 원리적으로 못 잡는다**는 것도 확인했다
(`seedPrev()` 가 `number`/`boolean` 만 심어 배열 안을 안 채운다). **부분 이월 단언을 신설해 뒀다.**
⚠️ 전환 후 `prev` 를 다시 해싱하는 경로를 만들면 이 근거가 깨진다 — 그때는 `slice()` 로 바꾸고
그 테스트의 `toBe` 를 `toEqual` 로 **함께** 고쳐라(주석에 적어 뒀다).

### 2-5. 뮤테이션 9건 전부 KILLED — 그리고 음성 대조 하나가 실제로 뒤집혔다

`onVolleyFired` 의 음성 대조 초안을 "사거리 안 표적 없는 첫 틱"으로 잡았더니 **웨이브 디렉터가
그 시드에서 사거리 안에 적을 낳아** 실패했다. 쿨다운 게이트로 다시 세웠다.
**계측기를 뮤테이션 없이 믿지 마라** — 이 레인에서만 두 번째다.

### 4-1. 왜 합치는가

촉매도 **골든 전량 재생성 + EF 재배포**를 부른다(ADR-0052 §귀결). 210스킬도 같다.

시그니처를 커밋 2 에 합친 것). **합쳐야 할 것은 PR 이 아니라 골든 재생성 창이다.**

### 4-2. `audit.md`(5판 전수 대조표)에서 지금 알아야 할 것

### 4-3. 겹침 판정 — **공용 30종 완료. 특산 18종은 미완**

> **판정: S0 기반은 촉매를 「자리」로는 대부분 받지만 「형태」로는 한 장도 못 받는다.**

앵커 9개의 본체가 **전부** 이 두 줄로 시작한다:
```ts
if (!state.skillsOn) return;   // = 스킬 투자가 하나라도 있는가
switch (state.sigBit) { … }    // = 기체 시그니처 디스패치
```
촉매는 ①스킬 투자와 무관하고 ②기체와 무관하다. **무투자 런에 촉매만 켠 경우 앵커가 첫 줄에서
즉시 반환**하고, 켜지더라도 `sigBit` switch 에 촉매가 들어갈 `case` 가 없다.
→ **앵커를 그대로 재사용할 수 있는 촉매 0종.** 지점(위치)은 8/9 가 재사용 가능하다.

**처방**: 앵커 본체를 `dispatchSkill(state, …)` / `dispatchCatalyst(state, …)` **두 호출로 쪼개고
파일을 `skillHooks.ts` / `catalystHooks.ts` 로 가른다.** 안 그러면 **7 스킬 레인 + 촉매 레인이 같은
파일의 같은 9개 함수를 동시에 만진다** — S0 가 격리를 `world.ts` 에서 옮겨 온 이득이 그대로 사라진다.
